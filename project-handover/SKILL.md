# project-handover — 跨 AI 项目交接体系

> 解决的问题：**同一个工作目录被不同 AI、不同会话轮流接手，每次都要重新摸索**，
> 且前一个 AI 的错误结论会被后一个沿用。
> 做法：把"必需上下文"固化成仓库内的三份文件，做到**自包含 + 可验证 + 可纠错**。

## 一、三层结构（为什么是三层）

| 层 | 文件 | 解决的问题 | 关键要求 |
|---|---|---|---|
| **发现层** | `<项目根>/AGENTS.md` | AI **不知道要读什么** | 主流 AI 编码工具会**自动读取工作区根目录的 AGENTS.md** → 这是唯一能"自动被发现"的位置。**≤150 行**，含开场三步 + 硬红线 + 任务路由 |
| **权威层** | `交接文档-<项目>.md` | AI **不知道全貌** | **自包含**（读它不需要任何历史对话）；带**口径 + 时点**；与 AGENTS.md 冲突时以它为准 |
| **验证层** | `工具/check_env.sh` | AI **不知道环境能不能用** | 纯只读、**10 秒内**、输出 `[OK]/[WARN]/[FAIL]`、结尾给结论 |

**分层原则**：发现层只放"30 秒能看懂 + 该去哪读"；权威层放全量与证据；两者**刻意重复一小部分**（红线、路由），换取"只读一层也能开工"。权威层为唯一真相源。

> ⚠️ **Claude Code 例外（每次必做）**：Claude Code **不原生读取 AGENTS.md**，只认 `CLAUDE.md`
> （截至 2026 年中）。只放 AGENTS.md 的目录，Claude Code 会**静默加载零条指令**——不报错，
> 但什么都没生效，极难排查。零成本解法：同目录再放一个只有一行 `@AGENTS.md` 的 thin `CLAUDE.md`
> （或 `ln -s AGENTS.md CLAUDE.md`；Windows 建软链需管理员权限，故推荐 @import 写法）。
> **AGENTS.md 保持唯一真相源，CLAUDE.md 只做桥接，绝不重复写内容。**

## 二.B 库级 + 项目级：多目录模式

> 当用户希望**多个目录都做交接**（笔记库下多个项目、monorepo 多包、多账号工作区）时，走这条。

### 两层分工

| 层 | 位置 | 放什么 | 不放什么 |
|---|---|---|---|
| **库级** AGENTS.md | 库/仓库根 | 库的整体结构、**项目入口清单**、跨项目通用纪律、公共工具路径、总红线 | 任何单项目特有内容 |
| **项目级** AGENTS.md | 各项目目录 | 该项目定位、硬红线、任务路由、能力边界、目录速查 | 已在库级说过的通用话 |

### 三条铁律（**各家工具合并行为不一致，这是硬约束**）

实测各工具对嵌套 AGENTS.md 的处理**并不统一**：

| 工具 | 嵌套 AGENTS.md 行为 |
|---|---|
| Codex | 从项目根**向下拼接**到 cwd，后来者覆盖；合并总大小上限 32 KiB |
| Cursor | 嵌套与父目录**合并**，更具体的优先 |
| GitHub Copilot | **最近的一个胜出（不合并）** |
| Amp / Warp | cwd 及父目录总包含；subtree 文件在触碰该子树时才加载 |
| agents.md 官方 FAQ | "closest AGENTS.md wins" |

由此推出：

1. **每层必须自包含，项目级不许依赖库级**。
   用 Copilot 时库级内容**完全不会被加载**——项目级里若只写"详见库级 §3"，接手者会拿到断链。
   库级只做**地图**（"库里有哪些项目、各自入口在哪"），不做**必需上下文**。
2. **库级必须有「项目入口清单」**：一个表格列出所有项目 + 各自交接文档路径 + 一句话定位。
   这是库级唯一真正不可替代的价值。
3. **能下沉就下沉**：只有跨项目通用的东西才放库级，其余一律进项目级，避免库级膨胀
   （Codex 有 32 KiB 上限，超过会静默停止追加文件）。

### 库级骨架

用 `assets/AGENTS.library.template.md`。核心就是三块：
库是什么 → **项目入口清单（表格）** → 跨项目通用纪律（命名/git/红线）。

### 批量落地

对 N 个目录做交接时，**不要一次生成 N 份完整文档**（容易批量产出同质化废话）。
正确顺序：

1. 先对每个目录跑 Step 1 勘察 + Step 2 冲突审计（**这一步不能省，也不能批量**）；
2. 库级 AGENTS.md 先落地（此时项目入口清单可以留 TBD）；
3. **一次做一个项目**的 AGENTS.md + 交接文档，做完回填库级清单；
4. 每个目录都要放 `AGENTS.md` + `CLAUDE.md`（桥接）+ `工具/check_env.sh`。

## 二、执行步骤

### Step 1 · 实地勘察（**禁止凭想象写**）

先跑事实采集，别急着写文档。至少拿到：

```bash
cd <项目根>
# 目录结构与规模
ls -la; find <各子目录> -type f -not -name '.DS_Store' | wc -l
# 是否已有 AI 入口文件（常见缺口）
ls -a | grep -iE 'agents|claude|cursor|copilot|readme'
# 版本控制真实结构（★极易踩坑，见 Step 2）
git rev-parse --show-toplevel
git status --short | head -30
# 依赖：技能/脚本/凭据/缓存是否存在
ls ~/.workbuddy/skills/ ; ls ~/src/skills/
```

### Step 2 · ⚠️ 冲突与陷阱审计（**这一步最容易被跳过，也最值钱**）

接手者最大的风险不是"信息不足"，而是**继承了错误信息**。逐项审计：

1. **多份文档口径打架**——列出所有含同类结论的文件（如 `交接文档` vs `运营/数据结论.md` vs `memory/MEMORY.md`），
   比对同一指标。**以"最新跑数 + 最严口径"的那份为准**，并在文档里显式标注"旧结论已作废 + 作废原因"。
2. **统计假象**——凡"均值/倍数"类结论，检查是否**剔除极端值 + 分层**。
   典型症状：用 3 篇爆款冒充规律（未剔 TOP3）、用全量样本算标题特征（未按粉丝规模分层）。
   发现即**判定该结论作废并重算**，不要照抄。
3. **时点缺失**——任何数字必须有"口径 + 时点"（如"147 篇 · 09-18 口径"）。
   无时点的数字会让接手者误判，**补上或删掉**。
4. **git 仓库根 ≠ 项目目录**——很多项目是"大仓库里的子目录"。影响：索引路径要带 `./` 前缀、
   `git status` 会连带旁支改动、`git add -A` 会跨目录。**必须实测并写明**。
5. **`AD` / `D` 状态的文件**——可能是"索引有、工作区无"。别当垃圾：
   `git show ":0:./<path>"` 可取回（`./` 前缀不可省）。**先查证再动，不要擅自恢复或删除**。
6. **能力边界**——哪些操作**物理上做不到**（账号权限、接口未授权、登录态要求）。
   必须显式列出，否则接手 AI 会在死路上反复试错。
7. **自称"自包含 / 读这份就够"的文档，必须实测验证**——**别因为它写了就信**。
   实践案例：某项目交接 SOP 开头写着"本文件全自包含，读完本页即可直接开工"，
   但「某脚本默认参数是另一个账号 → 会误判结果」「写库须双写某派生列」「沙箱报 IOERR 的绕过办法」
   这些**致命坑只存在于另一份 memory 文件里**，SOP 里没有。
   → 验证方法：把文档声称覆盖的主题逐项 grep，重点查**高风险操作**
     （写库 / 删除 / 发布 / 跨账号 / 需要登录态）是否都有说明；缺口补进 AGENTS.md，
     并在原文档顶部加指向，**不要重写用户精心维护的文档**。

### Step 3 · 写 `AGENTS.md`（发现层）

用 `assets/AGENTS.template.md` 为骨架，至少包含：

- **§0 这是什么**：一句话定位 + 关键硬数据（带时点）
- **§1 新会话开场三步**：跑 `check_env.sh` → 读交接文档 → 查重/按路由干活
- **§2 硬红线**：不可违反的（合规/纪律），每条给"违反后果"
- **§3 能力边界**：做不到的 + 需登录态的 + 替代路径
- **§4 任务路由表**：用户说 X → 做什么 → 用哪个工具（**最高价值的一节**）
- **§5 目录速查** + **§6 文件纪律**

### Step 4 · 写/修 `交接文档-<项目>.md`（权威层）

骨架见 `assets/交接文档.template.md`。修订既有文档时：
- **不要推倒重写**——保留仍然正确的内容，只改错的、补缺的。
- 若修正了旧版的重大错误，**在开头显式告警**（"本次 vN 修正了 v1 的 XX 错误，若你读过 v1 请以本版为准"）。
- **必须留「修订记录」表**（日期 / 版本 / 修订人 / 内容），让接手者知道哪些是新改的。

### Step 5 · 写 `工具/check_env.sh`（验证层）

复制 `assets/check_env.template.sh`，按项目实际改检查项。硬要求：
- **纯只读**（不做任何写操作）
- **10 秒内**跑完（别在里面跑重量级脚本）
- 输出 `[OK]/[WARN]/[FAIL]` 三档（**别用 emoji**，保证任何终端/AI 都能解析）
- 结尾打印 `结论: N 项正常, M 项注意, K 项阻塞` + 一句行动建议
- 有 `[FAIL]` 时 `exit 1`

### Step 6 · 空降演练（**最能暴露问题的一步，别省**）

自己写的文档自己看不出毛病。做法是**启动一个零上下文的 AI**（子 Agent）去空降：

```text
你是一个刚接手工作的 AI 助手，没有任何历史对话上下文。
工作目录：<项目路径>
任务：在不询问任何人的前提下，仅通过阅读仓库文件，搞清楚
  ① 这目录是干什么的 ② 现在最该做什么 ③ 第一步执行什么命令。
硬性要求：只用 Read/Bash/Glob/Grep，**绝不提问用户**；
  只做只读探索，禁止推送/发布/删除/写库/移动文件。
报告必须包含：a) 按顺序读了哪些文件 b) 用了多少步 c) **诚实报告卡住的地方**
  （文档矛盾/缺失/断链/指向不存在的文件/写死的过期数字）d) 最终结论。
```

实测这一招能挖出自己看不出来的问题，典型三类：

| 演练暴露的问题 | 根因 | 对策 |
|---|---|---|
| 「找不到现在该干什么」 | 文档只有流水线，**没有待办指针** | AGENTS.md 必须有「现在该干什么」节（见下方铁律 2） |
| 「文档数字和实际对不上」 | **写死了会变的数字** | 改为「量级 + 查法」（见下方铁律 1） |
| 「照文档抄命令却跑不通」 | 路径是相对别的目录写的 / 命令有隐藏前置（某环境变量没设） | 命令一律实测；路径优先写绝对路径 |

> 演练还常顺带发现**真正的 backlog**：某项目演练时才发现，最大的一块活
> （近千条待分拣线索 + `inbox`/`promote`/`ignore` 一整套流程）**根本没写进 SOP**，
> 只在工程中枢自己的 README 里有。→ **交接文档要覆盖"当下最该干的活"，不只是"流程怎么走"**。

### Step 7 · 验证（**不可省**）

```bash
bash 工具/check_env.sh                  # 必须真跑，别只写不跑
# 文档里给出的每条命令都要实测一遍——
# 特别是含中文/全角字符路径的 git 命令（极容易给出跑不通的指引）
```

### Step 8 · 沉淀

- 在项目 `memory/MEMORY.md` 追加"入口与交接体系"一节（三入口位置 + 维护规矩）。
- 追加当日工作日志（append-only）。
- 把演练暴露的问题**回写进技能**（本文件的§三 已知坑）。

## 二.C 两条铁律（**空降演练实测得出，违反必返工**）

### 铁律 1 · 🔴 动态数据绝不写死

演练实测：早上跑出的「待分拣线索 859 条」写进 AGENTS.md，**几小时后变成 908**——
同一天就漂了；另一处「监控源 1832」也变成 1854。接手者拿文档数字当现状会直接误判。

**正确写法**：给「**量级 + 查法 + 命令**」，不给具体值。

```markdown
| 待分拣线索 ⚠️ | `job_ctl.py inbox` | 近千条 —— 当前最大 backlog |
```

只有**变化慢的事实**（累计文章数、累计阅读、粉丝数）才可以写死，且**必须带时点**
（如"147 篇 · 09-18 口径"）。凡"每天都在动"的指标，一律只写查法。

### 铁律 2 · 🔴 每个 AGENTS.md 必须有「现在该干什么」节

演练实测：**两个不同项目**的空降 AI 都反馈同一句话——
"文档只给了流水线，没有说明下一个做什么，我只能靠推断"。

没有待办指针 = 接手者每次都要重新推一遍，这**违背交接的意义**。

- 有 TODO / 排期文件的：直接指向它，并在 AGENTS.md 摘一份摘要表（时间窗 × 状态）。
- **没有 TODO 文件的**：别装作有——写明「本目录无待办看板，下一个做什么需从 X 与 Y 比对推断」，
  并**建议项目主补一个 `待办.md`**。诚实标注缺口，比给一个含糊的指向有用。

## 三、已知坑

1. **给出的命令必须实测**。本次实践中，`git show ":path"` 在"项目目录 ≠ 仓库根"时**必然失败**，
   正确写法是 `git show ":0:./path"`。凭直觉写的命令会把接手者带进沟里。
2. **`AGENTS.md` 要短**。超过 ~150 行就没人读完了；细节一律推到交接文档。
3. **别只写"有什么"，要写"什么时候用"**。目录清单的价值远低于"任务 → 动作"路由表。
4. **别替人下结论**。发现异常状态（如文件被删、数据对不上）应**建立告警 + 给查证命令**，
   而不是擅自恢复/删除。
5. **同一事实只在一处详述**。AGENTS.md 与交接文档重复太多会分叉——
   约定"交接文档为准，AGENTS.md 只做索引"。
6. **数字必须可复算**。写"147 篇 / 444,159 阅读"要能说清来源文件与口径；
   推算值必须标注"推算"。
7. **别假设 AGENTS.md 一定被读到**。Claude Code 原生不读它（须配 thin `CLAUDE.md` 桥接）；
   多层嵌套时 Copilot 之类只取"最近的一个"（不合并）。→ **每层自包含 + 必配桥接文件**。
8. **库级与项目级内容不要重复**。重复必然分叉。库级只放"地图 + 通用纪律"，
   具体一律下沉到项目级；项目级不写"详见库级 §X"（Copilot 下会断链）。
9. **多目录不要一次性批量生成 N 份**。会产出结构相同、内容空泛的废话文档。
   必须**一次做一个**，且 Step 1 勘察 / Step 2 冲突审计不可跳过——
   真正的价值恰恰来自"每个项目各自踩过的坑"，那东西批量不出来。

## 四、模板

| 模板 | 用途 |
|---|---|
| `assets/AGENTS.template.md` | 项目级发现层骨架（单项目） |
| `assets/AGENTS.library.template.md` | **库级**骨架（多目录场景）+ CLAUDE.md 桥接说明 |
| `assets/交接文档.template.md` | 权威层骨架 |
| `assets/check_env.template.sh` | 验证层脚本骨架 |
