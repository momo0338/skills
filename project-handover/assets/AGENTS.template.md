## 2. 三条硬红线（违反即删文 / 封号，无例外）

1. **AI 合规**（微信 2026-03-27 新规）：非真人自动化创作可删文封号。
   → 稿中**必须有满爸本人的真实表达**（亲历、观点、口语化）。**AI 绝不可代写第一人称经历**，
   只能留占位 `【满爸亲历·待补】` 让本人补。
2. **标题欺诈**：算法比对标题承诺与正文，不兑现即降权。
   → 标题说「这 9 家别去」，正文就必须明确列出 9 家（数量对齐）。
3. **发布纪律**：必须**标原创 + 全量群发**。
   → 分组群发、关闭推荐开关、非原创转载，会**直接失去公域推荐资格**。

**另有两条元规则**：
- **不确定就查证，不要编**：所有数据必须能从 `发表记录*.csv` / 原始 JSON 复算，推算值必须标注。
- **不要替人下结论**：发布与否、标题定夺、勾稽匹配结果，都留给满爸本人拍板。

## 6. 文件纪律

- **命名成对**：`<标题>.md` ↔ `<标题>-排版.html`（+ `-封面.jpg` + `__assets/`）；迭代版用 `-v2` / `-v3`，**不覆盖旧版**。
- 所有 md 带 frontmatter：`title / date / category: 满爸爱生活 / tags`。
- **时效稿不写死时间**：标题里写「×月×日」或「这个月的免票日」，别写「本周六」（过期反噬）。
- **内存日志 append-only**，不覆盖重写。

### git 结构（会坑到你，先看）

**本目录不是 git 仓库根**——根在 `/Users/zhugx/codeup/obsidian/`，本目录（及隔壁 `码上职业/`）都是它的子目录。

- 索引路径**必须带 `./` 前缀**：`git show ":0:./待发布/xxx.md"`（否则报 `path ... is in the index, but not '待发布/xxx.md'`）。
- `git status` 会**连带显示旁支目录**（码上职业等）的改动，属正常。
- 别用 `git add -A`（会跨目录）；用 `git add <具体文件>`。
- 看到 `AD` / `D` 状态**先查证再动**：文件可能只在索引里，`git show ":0:./<path>"` 可取回。
