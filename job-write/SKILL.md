## 一、概述与定位（与 guide-write 的区别）

> **解耦原则**：本技能聚焦招聘类文章的「写什么、怎么结构、怎么排雷、怎么吃长尾、怎么推」。排版样式统一遵循 `mp-html` 原生方言，草稿推送交由 `mp-publish` 全链路执行（**账号固定 `mashang` = 码上职业**）。

| 维度 | guide-write（场馆攻略） | **job-write（招聘/校招）** |
|---|---|---|
| 核心素材 | 实拍图 + 个人体验桥段 | **官方公告/报名站硬信息**（岗位、条件、时间、人数） |
| 真实性红线 | 外观描写须实拍/官方证实 | **岗位/人数/学历/专业不得编造**，优先从官方报名站接口实拉 |
| 结构重点 | 五步攻略骨架 + 冷知识 | **8段骨架 + 校招岗位清单表 + FAQ 长尾块** |
| 转化位 | 留言/收藏/往期矩阵 | **社群 CTA（通用标题「招聘信息不漏接」+ 紧凑单卡 + 服务清单）、结尾即止** |
| 搜索打法 | 地域根词 + 具象奇观 | **标题必带「校招」+ 问句 FAQ + 合集聚类** |
| 合规特殊项 | 信息核实说明 | **不搬运原文、不声明原创、不复制别家二维码；防骗提醒必须留** |

**一句话**：guide-write 写"去哪玩、怎么玩"；job-write 写"招谁、要什么条件、怎么报、在哪看全部岗位"。

### ⛔ 明确不属于本技能范围（2026-09-18 朱总纠正后立规）

**判定标准只有一条：这份内容**有没有"当下可投递的公告与报名窗口"**。**

| 属于 job-write | ⛔ **不属于** job-write |
|---|---|
| 企业校招（A 线）｜事业单位/高校编制招考（B 线）｜企业社招 | **升学政策解读**：强基计划、综合评价、高考志愿 |

| 读者要"投不投、怎么投" | **无投递窗口**，读者要"够不够格、什么时候准备" |

⛔ **不得对"升学政策解读 / 体制内路径科普"套用本技能的**：数据三宫格、岗位清单表、求职向 FAQ 长尾块、「招聘信息不漏接」CTA + 服务清单、校招/社招封面母版。

## 二、写稿装配规范（决定质量与开销的一道坎）

> 这一节不是文风建议，是**最高纪律与绝对红线**。核心只有一句：
> **⛔ 严格禁止自作主张、自己推演！所有的内容必须是能核对源头网址公告或者文件等内容的才行。硬信息不进模型推理，只进投料单。**

### 2.1 为什么必须这样

让模型边找边写或自由发挥，会同时产生两个严重后果：

- **质量与事故**：找不到时它会"合理补全"或擅自推演。
  - 典型事故 1（2026-09-18 紫金银行）：按自媒体非官方来源写了「60 名 / 11-02 截止 / 11-08 笔试」，官方简章实为「45 名 / 10-24 12:00 截止 / 10 月下旬笔试」；
  - 典型事故 2（2026-09-24 南京市职防院）：未核查官方挂载的附件 xlsx，模型擅自根据常规业务脑补了公卫、理化、放射等多个虚构岗位，被朱总一眼识破，险发重大失真事故！
  - **铁律**：人数 / 截止日 / 岗位清单 / 招考条件 **必须 100% 能够核对源头网址公告原文、官方网申系统或官方挂载附件表格（xlsx/pdf）**。严禁模型基于机构业务常识擅自脑补；官方未披露的缺口一律写「公告未披露」，查不到权威官方源头文件一律严禁动笔！
- **开销**：查找必然带来多轮工具调用与正文回流，一次找不全还要重找。

把确定性前置到脚本，**同一个动作同时解决这两件事**。

### 2.2 三层装载

| 层 | 内容 | 体量 | 谁产出 |
|---|---|---|---|
| **L0 常驻** | 本文件：骨架 / SEO / 排版 / 封面 / 红线 / 自检 | ~15k token | 技能自带 |
| **L1 投料单** | 该单位硬信息 + **缺口清单** + 装配指令 | ~700 token | `emit_briefing.py` |
| **L2 就近范文** | 同类型最近一稿的**指定段落**（不是全篇） | ~300 token | 指定一篇已发布稿 |

⛔ **L0 不允许临时扩大**：不要为了让模型"多知道点"去通读 `references/`，
只有 §零 里写的那三类场景才读。

### 2.3 标准流程

```bash
# ⓪ 选活（**每天第一件事**）：出「硬信息已齐 + 尚未动笔」名单，**并强制与草稿箱对账**
python3 /Users/zhugx/src/skills/job-write/scripts/emit_briefing.py --ready
#    输出三段：主名单 / ℹ️按网申入口合并（同入口=1个写作单位）/ ⚠️疑似已在草稿箱
#    只做对账、不改名单：--draftbox-audit（逐条打印 草稿标题→DB批次+稿件状态）
#    换账号：--profile <别名>（默认 mashang）；确认未发才用 --include-suspect 并回主名单

# ① 出投料单（机器搬主档 + 标缺口，禁止让模型自己去找硬信息）
python3 /Users/zhugx/src/skills/job-write/scripts/emit_briefing.py "<单位关键词>"

# ② 投料单出现 ⛔ 缺口 → 先回官方补，补完**回填主档**再动笔。
#    截止日仍是软词（待核 / 预计 / 滚动 / 招满即止）的，脚本会判定「暂不可动笔」。
```

**为什么 ⓪ 不能跳（2026-09-21 立）**：`campaigns.has_article` 只反映**库里**有没有稿
（= `campaign_articles.rendered_html` 长度 >50），**不等于草稿箱真实状态** ——
推完草稿箱忘了回填，DB 会一直显示「未排」，照它选活就是重复劳动。
故 `--ready` 内置对账：对账键＝`campaigns.title` vs 草稿标题（不中再用「单位名主体前缀互含」兜底）。
⛔ 登录态失效时脚本**只降级告警、不自动登录**，此时名单不可直接采信。
同一网申入口的多条明细行（如 60 家农商行法人共用一个 51job 专题）会被合并为 1 个写作单位。

然后这样调用：

```
按 job-write 写 <期号-单位>。
硬信息只用投料单，缺口写「公告未披露」；
禁止推测、禁止引用转载号与聚合站的日期和人数。
语气参考 <最近一稿路径> 的导语与岗位表两段（只读这两段）。
写完跑 verify_draft.py，报错自己修到全绿再汇报。
```

**为什么指定"只读两段"**：给全篇会把那一稿的题材特征一起带进来；
给那两段（导语定语气、岗位表定结构）刚好够对齐，不到 300 token。

### 2.4 质控不进提示词

§八 的自检清单是**给人看的最终确认**，不要整段复制进提示词要求模型自检——
它会选择性忽略，而你还要为这段解读付费。成稿后跑脚本，让报错驱动修改：

```bash
/usr/local/bin/python3 \
  /Users/zhugx/src/skills/job-write/scripts/verify_draft.py "<稿件前缀>"
```

⚠️ **脚本有盲区**：它不比对"排版内容与源稿是否一致"。2026-09-18 曾发生 5 篇排版的
尾部被拼进别篇全文、`verify_draft` 却显示全绿。此项必须人工扫一遍：
正文讲的是本篇单位、无他单位强特征词、结尾 CTA 正常。

⚠️ **第二个盲区（2026-09-20 中信建投稿实测）**：`verify_draft` **不校验 HTML 标签配平**。
当日复用别篇 CTA 时用 `ref[idx:]` 截取，把别篇文件末尾的 `</body></html>` 带了进来，
导致根 `<section>` 被提前闭合、尾部出现游离标签——脚本仍报全绿。
**规戒**：① 复用别篇 HTML 片段时，**按标签配平截取**（计数 `<section`/`</section>`），
禁用"从锚点切到文件尾"；② 复跑质检后核对 **`<section` 与 `</section>` 数量相等**。
⚠️ **2026-09-21 实测修正（华泰稿）**：正常整篇 `-排版.html` 是**完整 HTML 文档**
（`<!DOCTYPE html><html><head>…</head><body>…</body></html>`），所以 `</body>`、`</html>`
**各恰好出现 1 次、且就在文件末尾**——中金、银河等已成功推送的稿件全部如此。
⛔ 旧版此处曾写「`grep -c "</body>\|</html>"` **应为 0**、结尾应是 `</section>`」，**与实物不符**：
照做会把正常稿误判为污染、甚至误删文档壳。**正确判据＝计数恰为 1 且仅在末尾；≥2 次才是**
「截取别篇尾部带回游离标签」的污染（这时才删多余的）。

## 四、SEO / 长尾优化（招聘类核心打法，已验证）

1. **标题必带「校招 / 2027校招」+ 单位 + 城市**（搜一搜标题权重远高于正文）。例：`江苏省铁路集团2027校招（10+15岗）`。标题 **≤64 个字符**（微信标题按字符计，不是字节——中文标题 40+ 字符很正常，实测 43 字符可正常推送），前 21 字含最强钩子。
2. **加「校招常见问答 FAQ」段（对齐微信搜一搜 Answer Box 抓取法则）**（放在"怎么报名"之后）：
   - **禁止内省式/书面化缩略提问**（如 ❌ "专业不对口有机会吗？"、❌ "能调回市区吗？"）。
   - **必须使用完整主谓宾的自然人真实搜索高频句**（含具体单位简称/岗位/意图词，便于微信搜一搜直出 Answer Box 问答精选卡片）：
     - **志愿类**：Q1 本次校招限报几个岗位？能同时投递几家二级分行/分公司？
     - **专业类**：Q2 非理工/非金融专业能报该单位的校招岗位吗？
     - **备考类**：Q3 该单位统考笔试考什么内容？行测与专业题占比多少？什么时候笔试？
     - **身体/体检类**：Q4 该单位体检有哪些硬性淘汰指标？色弱、转氨酶过高影响录用吗？
     - **工作生活/定向类**：Q5 县域支行/基层定向工作满约定年限后能调回市区吗？提供单身宿舍吗？
     - **身份与政策类**：Q6 录用后是正式合同工（正式编制）吗？往届生在择业期内算应届吗？能领南京租房补贴吗？
3. **发布后必勾合集**（如《2027年校园招聘》）做主题聚类，整栏搜权重更高。
4. **内容全程文字 / HTML（含表格）**，**绝不把岗位 / 条件做成图片**（图片不可索引，最伤搜索）。
5. **搜索/长尾与排版合规无关**：原生方言合规只影响渲染；只要内容是可索引文字，表格/section 都正常收录。真影响排名的是标题关键词、合集聚类、FAQ 问句、阅读分享等互动。
6. **SEO 摘要规范（digest，必产）**：
   - **长度**：≤120 个字符（微信 digest 硬上限）；写完必须实测字符数，超了先砍修饰语。
   - **四禁**：无 emoji（豆腐块）；无 HTML/换行；**不复述标题**（标题已展示，摘要要补增量）；不写空话（"机会难得""不容错过"）。
   - **四必含（搜一搜核心检索词密度）**：①报名**截止时间与笔试预计时点**（如"10月8日网申截止，10月底笔试"）；②1–2 个**硬门槛钩子**（人数/学历/专业限制/定向年限）；③官方**入口域名**（如 `job.icbc.com.cn`，明确官方出处）；④核心差异点（如"除科技岗外专业不限""辖内不含苏州"）。字数严控在 105~118 字符，充分利用空间且不超限。
   - **存放**：有 `-源稿.md` 的写在 h1 之后一行（**单行式，本专栏通用写法**）：
     `> **SEO 摘要**（NNN字，无 emoji）：<摘要正文>`
     两行式（`> **SEO 摘要**（NNN字，无 emoji）：` + 换行 `> <摘要正文>`）同样被支持，二选一即可。
     流水线自动提取，**日志须显示「摘要(手动) N 字符」**；无源稿的用 `--digest` 传参。
     ⚠️ **2026-09-17 修 Bug**：旧正则只认两行式，单行式会**静默回退成「摘要(自动(正文开头兜底))」**——
     写了却没用上。已修（`mp-publish/scripts/wx_pipeline.py` 支持两种写法）。**推前务必看日志那行。**
   - ⚠️ **正文里出现半角冒号不影响提取**（如 `16:00`），但**总字数必须实测 ≤120**；写 120+ 会被平台截断/回退。
     建议写成后立刻 `len()` 实测，超了先砍修饰语（泰州初稿 128 字即超限，栖霞定稿 113 字）。

## 五、排版（强制遵循微信原生方言）

必须先读 `mp-html` 技能。本流水线专用要点：
- **桌面宽屏居中约束（铁律）**：首层外包装根 `<section>` 必须显式声明 `max-width:677px; margin:0 auto; box-sizing:border-box;`。微信后台及桌面浏览器会按窗口展开，若不加 `max-width:677px; margin:0 auto;` 会撑满屏幕变成两端宽屏拉伸；加上后桌面端优雅居中，手机端自适应 100% 满屏填满。
- **色彩规范（主体 VI 优先）**：
  - 严禁千篇一律通篇通用蓝（`#1a73e8`），**正文主色调必须跟随内容主体的官方 VI 标准色**。
  - 查验路径：官网/官微/VI手册，两源一致才采。
  - 主色应用位：导语卡底/边框、章节大标题数字竖条、大表表头底色、斑马纹浅色底、FAQ 问句重点色、CTA 渐变底。（「专栏抬头卡渐变底」随抬头卡废弃，2026-09-16 起不再有）
  - 白字对比度必须达标（$\ge 4.5:1$）；功能色（截止红 `#ea4335`、通过绿 `#558b2f`、解读黄 `#78350f`）不跟 VI 走，保留语义。
  - 典型电力央企 VI 参考：中国华电（海蓝 `#0F3C88` + 天蓝 `#0070C0`）、国家电网/南瑞（国网绿 `#006747` / `#007A5E`）、国家能源集团（国能红 `#C8102E` / `#E02B20`）、中国华能（华能红 `#D9001B` + 深海蓝 `#003366`）、中国核电（中核蓝 `#004B97` + 橙 `#FF7F00`）。
- 块级容器**只用 `<section>`**，禁 `<div>`（含块级子元素会被溶解丢样式）。
- **加粗克制原则（对照搜一搜教程01）**：
  - 微信明确指出："过度使用加粗标记会让用户迷失，也不利于搜索引擎识别文章重点"。
  - **严禁整段通篇加粗、严禁列表项句句加粗**。正文每屏（约300字）内，加粗词句**严格控制在 1~2 处最具决策价值的硬核事实**（如具体人数、截止时点、关键定向年限、排他性条件）。序数词（如"1."、"2."）、过渡句一律使用正常字重。
- 禁 `position:*`；禁 `<a href>`；禁 `style` 值里写 `&#39;`。
- 首层 wrapper 只放字体属性与居中约束，**不设水平 padding**（否则与微信正文容器双重内缩，"没拉满"）。
- 校验：方言合规检查属于底层通用技能 `mp-html`，调用 `/usr/local/bin/python3 /Users/zhugx/src/skills/mp-html/scripts/wx_dialect_check.py <html>` → 必须打印 `✅ 方言校验通过`。本地成稿后推荐直接使用 `scripts/verify_draft.py` 执行三件套一体化门禁质检。
- ⚠️ 校验脚本依赖 `bs4`，用 `/usr/local/bin/python3` 跑（托管 venv 裸装版没 bs4）。

```python
from PIL import Image, ImageDraw
master = Image.open(f"{BASE}/素材/封面母版/标准社招封面母版.png").convert("RGBA")  # 900×383

pad_x, pad_y, radius, cap_x, cap_y = 16, 8, 10, 40, 32
cap_w, cap_h = lw + pad_x * 2, LH + pad_y * 2
layer = Image.new("RGBA", master.size, (0, 0, 0, 0))
d = ImageDraw.Draw(layer)
d.rounded_rectangle([cap_x, cap_y, cap_x + cap_w, cap_y + cap_h], radius=radius,
                    fill=(255, 255, 255, 240), outline=(220, 230, 242, 255), width=1)
layer.alpha_composite(logo, (cap_x + pad_x, cap_y + pad_y))
out = Image.alpha_composite(master, layer)
out.convert("RGB").save(OUT, "PNG")     # ⚠️ 存 RGB：RGBA PNG 推草稿时会崩（JPEG 不支持 alpha）
```

3. **封面 (PNG)**：尺寸必须为 900×383；色彩模式必须为 RGB（严禁 RGBA）。

质检全绿通过后，稿件方可入库 `待发布/` 并标记就绪。

> ⚠️ 全绿 ≠ 完事：脚本有两个盲区（不比对排版与源稿内容一致性、**不校验 HTML 标签配平**），
> 推前必做人工复核，详见 §2.4。

## 七、合规红线（逐篇必查）

- **回官方核硬信息（岗位/人数/学历/专业/截止日）——招聘站是 SPA 时，抓它的 API**：
  - 南京银行：`job.njcb.com.cn` 是 Vue SPA → 抓 `static/js/app.*.js` 拿到 **`API_ROOT = //job.njcb.com.cn/recruit/api`** →
    **`POST /school/getSchoolNotic`**（body `{}`，带 UA + Referer）直接返回**校招公告全文 HTML**（2026-09-17 实测 7096 字）；
    另有 `/index/getMainInfo`（行简介）、`/notic/getNoticContent`（其他公告）、`/school/getSchoolContent`。
  - 通用套路：**页面无正文 → 抓 JS bundle → grep `API_ROOT` 与 `'/xxx/yyy'` 形式的接口常量 → POST 探活**。
  - 同类 CMS 可直接试同路径（苏皖多家银行官网/招聘站用同一套 huilan/eportal 模板）。
  - ⭐ **51job「省域系统级校招」专题站（2026-09-18 江苏农商行系统实证，一稿覆盖 42 家法人）**：
    - 入口 `campus.51job.com/<项目名>` 首页只是**视频引导页**，真正的列表在 **`/p1.html`**（含 `js/data.js`、`js/company.js`、`js/main.js`）。
    - **`js/data.js` 的 `addList`** = 全部法人/分行清单（`{addr:城市, addr2:行名, id}`；**被注释掉的行＝本轮未开放**，别算进去）。
    - **各分行简章在 `api/{id}.htm`**（纯静态片段，`requsetAJAX` 里 `url:"api/"+id+".htm"`）——curl 带 UA 直取，**一次拿到该行完整简章 + 岗位表**（岗位/专业/人数/学历）。
    - 解析要点：岗位表列序**各行列名不一**（「招聘岗位/职位/岗位名称」×「招聘人数/人数/职数」×「岗位类别/类别」），**必须按表头文字定位列**（不能写死 col3），并正确处理 **rowspan + colspan**（合计行、管培生行常是 colspan）；无 `<table>` 的行简章总数在正文句「本次招聘…员工 **N** 名」/「**N** 个岗位虚位以待」。
    - 类别归一：无「岗位类别」列时**从岗位名推断**（金融投资岗→金融投资类、管培生→管培、科技储备岗→金融科技类、通用岗/综合营销/柜面→金融业务类）。
    - **口径红线**：公告常写「全系统 N 家法人」（如 60 家），但报名站实际开放的**参与法人可能更少**（江苏农商行＝42 家）→ 正文必须如实写「本轮开放 X 家」，**别把全系统家数写成可报家数**。
    - 交付升级：公告只给总量时，**逐家拉 `api/{id}.htm` 拼成「各分行岗位一览」表**（分行/城市/人数/类别），比只写"详见简章"强得多；总人数与公告"1200+"互校吻合即采。

- **不做原文搬运**：只提炼事实（单位、岗位、条件、时间、报名方式）+ 自己的解读整理。
- ⛔ **不写页脚**（朱总 2026-09-16 立规）：**「来源行」「免责/版权声明」「下期预告」三类一律不加**，正文以社群 CTA（并排双码）结束。
  - 「信息来源：…｜整理：…」「官方源头：…｜招考政策以单位实时公告为准」→ 不加
  - 「本文仅作高校应届生求职信息汇编与政策解读…版权归 X 所有」→ 不加
  - 「下期预告：…欢迎锁定关注！」→ 不加（预告了却没发＝落空；已推 32 篇里 14 篇有，2026-09-16 已批量清除）
- ✅ **但「防骗提醒」必须留**：报名入口处的红框提醒（「校园招聘不收取任何费用，未授权任何机构或个人开展考前辅导、内推；凡『付费保过』『内部名额』均为骗局」）；有独立「防诈防骗特别提醒」节的（如国家能源集团）连 **网申技术热线 + 必须 PC 端 Chrome 填报** 一起保留——这类是可操作的读者保护信息，与上面三类不同。
- **不复制原文二维码 / 海报**（别家引流码），CTA 只放自己的双码。
- **不声明原创**（汇编类易被判滥用原创）。
- **时效标注**：每篇标原文发布日 + 截止日，过期稿不发。
- **「阅读原文」跳官方源**：用 `--source-url` 指官方报名站 / 官网 / 官微，不指自己的汇编稿。

## 十、与 guide-write 协作边界

- 同一篇"招聘 + 探店/打卡"混合内容（如"去某公司笔试顺路逛了XX馆"）：以**招聘为主**走 job-write，场馆部分可借用 guide-write 的实拍/去AI味规范，但**岗位硬信息必须用 job-write 的实拉+核验口径**。
- 纯场馆/攻略内容：**不要**用 job-write，交给 guide-write。

---
