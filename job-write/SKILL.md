## 一、概述与定位（与 guide-write 的区别）

> **解耦原则**：本技能聚焦招聘类文章的「写什么、怎么结构、怎么排雷、怎么吃长尾、怎么推」。招聘主数据只通过用户级 `ijob` 技能的版本化只读契约获取，禁止直连 ijob 数据库或解析内部 CLI。排版样式统一遵循 `mp-html` 原生方言，草稿推送交由 `mp-publish` 全链路执行（**账号固定 `mashang` = 码上职业**）。

| 维度 | guide-write（场馆攻略） | **job-write（招聘/校招）** |
|---|---|---|
| 核心素材 | 实拍图 + 个人体验桥段 | **官方公告/报名站硬信息**（岗位、条件、时间、人数） |
| 真实性红线 | 外观描写须实拍/官方证实 | **岗位/人数/学历/专业不得编造**，优先从官方报名站接口实拉 |
| 结构重点 | 五步攻略骨架 + 冷知识 | **8段骨架 + 校招岗位清单表 + FAQ 长尾块** |
| 转化位 | 留言/收藏/往期矩阵 | **社群 CTA（通用标题「招聘信息不漏接」+ 紧凑单卡 + 服务清单）、结尾即止** |
| 搜索打法 | 地域根词 + 具象奇观 | **标题必带「校招」+ 问句 FAQ + 合集聚类** |
| 合规特殊项 | 信息核实说明 | **不搬运原文、不声明原创、不复制别家二维码；不放防骗提醒** |

**一句话**：guide-write 写"去哪玩、怎么玩"；job-write 写"招谁、要什么条件、怎么报、在哪看全部岗位"。

## 二、写稿装配规范（决定质量与开销的一道坎）

> 这一节不是文风建议，是**最高纪律与绝对红线**。核心只有一句：
> **⛔ 严格禁止自作主张、自己推演！所有的内容必须是能核对源头网址公告或者文件等内容的才行。硬信息不进模型推理，只进投料单。**

### 2.1 为什么必须这样

让模型边找边写或自由发挥，会同时产生两个严重后果：

- **质量与事故**：找不到时它会"合理补全"或擅自推演。
  - 典型事故 1（2026-09-18 紫金银行）：按自媒体非官方来源写了「60 名 / 11-02 截止 / 11-08 笔试」，官方简章实为「45 名 / 10-24 12:00 截止 / 10 月下旬笔试」；
  - 典型事故 2（2026-09-24 南京市职防院）：未核查官方挂载的附件 xlsx，模型擅自根据常规业务脑补了公卫、理化、放射等多个虚构岗位，被朱总一眼识破，险发重大失真事故！
  - **铁律**：人数 / 截止日 / 岗位清单 / 招考条件 **必须 100% 能够核对源头网址公告原文、官方网申系统或官方挂载附件表格（xlsx/pdf）**。严禁模型基于机构业务常识擅自脑补；官方未披露的缺口一律写「公告未披露」，查不到权威官方源头文件一律严禁动笔！
- **开销**：查找必然带来多轮工具调用与正文回流，一次找不全还要重找。

把确定性前置到脚本，**同一个动作同时解决这两件事**。

### 2.2 三层装载

| 层 | 内容 | 体量 | 谁产出 |
|---|---|---|---|
| **L0 常驻** | 本文件：骨架 / SEO / 排版 / 封面 / 红线 / 自检 | ~15k token | 技能自带 |
| **L1 投料单** | 该单位硬信息 + **缺口清单** + 装配指令 | ~700 token | `emit_briefing.py` |
| **L2 就近范文** | 同类型最近一稿的**指定段落**（不是全篇） | ~300 token | 指定一篇已发布稿 |

⛔ **L0 不允许临时扩大**：不要为了让模型"多知道点"去通读 `references/`，
只有 §零 里写的那三类场景才读。

### 2.3 标准流程

```bash
# ⓪ 选活（**每天第一件事**）：出「硬信息已齐、库内未成稿、草稿箱未命中候选」名单
python3 /Users/zhugx/src/skills/job-write/scripts/emit_briefing.py --ready
#    输出三段：主名单 / ℹ️按网申入口合并（同入口=1个写作单位）/ ⚠️草稿箱候选
#    只做对账、不改名单：--draftbox-audit（逐条打印 草稿标题→DB候选批次+库内稿件状态）
#    换账号：--profile <别名>（默认 mashang）；确认候选确未发才用 --include-suspect 并回主名单

# ① 出投料单（机器搬主档 + 标缺口，禁止让模型自己去找硬信息）
python3 /Users/zhugx/src/skills/job-write/scripts/emit_briefing.py "<单位关键词>"

# ② 投料单出现 ⛔ 缺口 → 先回官方补，补完**回填主档**再动笔。
#    截止日为空/软词/哨兵日/历史「发布日 +30 天」占位，脚本均判「暂不可动笔」。
```

**为什么 ⓪ 不能跳（2026-09-21 立，2026-09-25 修正）**：`ijob` 契约返回的 `content_state`
（`unwritten` / `written` / `published`）只反映 **ijob 侧有没有成稿**，
**既不等于已推微信草稿箱，更不等于已发布**。推完草稿箱若尚未在 ijob 项目完成正式回填，
契约仍可能显示 `unwritten`，照它选活就会重复劳动。
故 `--ready` 内置对账，按 `campaign_id` 排除已命中的草稿候选：
标题精确 → ijob 侧可检索正文含标题 → 批次标题主体互含 → 单位主体相似 → 人工维护的简称/全称别名。
**正文多批次、标题多批次以及后三级弱匹配都只作人工核验候选，禁止自动回填或宣称确定失同步**；
审计同时给原始草稿行数、唯一标题数、展示映射批次数和完整排除批次数，避免重复标题或同品牌旧批次
放大统计。歧义命中仅优先展示“已发布 > 库内已成稿 > 库内未排”的记录，但 `--ready` 仍排除全部可能批次。
⛔ 登录态失效时脚本**只降级告警、不自动登录**，此时名单会明示「不可直接采信」。
同一网申入口的多条明细行（如 60 家农商行法人共用一个 51job 专题）会合并为 1 个写作单位。

**截止日占位红线**：历史导入曾把未核实截止批量写成 `publish_date + 30 天`。
脚本会降级此类日期，必须回官方核实后回 ijob 项目按其内部写操作 SOP 复核；
流程公告、导航页、长期招聘门户不应因有日期就进入普通倒计时选题池。

🔴🔴 **`[miss] ijob 无匹配批次` = 高危信号，不是"查不到而已"（2026-09-28 中国联通稿实测立规）**：
`emit_briefing.py "<单位关键词>"` 返回 `[miss]` 时，说明**该单位从未进过主数据源**。
此时手上的稿子极可能是**绕过投料单、模型自拟硬信息写出来的**——不是"信息待补"，是**信息已假**。
✅ **必做**：动任何一篇 `[miss]` 单位的稿子前，先跑这条**批量验尸命令**，
把"编造话术指纹"逐篇计数（见下 §2.5），命中即整篇打回重写，**不要逐句润色**。

### 2.5 🔴 编造话术指纹清单（2026-09-28 立规，来自三家运营商稿同病实测）

**事故形态**：一次给 3 家（电信/移动/联通）写稿，模型给**每一家都套了同一批"央企校招套话"**——
CET-4 425／CET-6 425、「行测言语理解数理逻辑资料分析判断推理」、「色盲色弱对一线通信岗有明确限制」、
「A类正式编制」「六险二金／企业年金／补充医疗」、「食堂+青年过渡公寓+通勤班车」、
「南京落户由单位协助办理」、「雏鹰启航培养计划」、「项目制承包分红」。
**逐条回官方原文检索，结果几乎全为 0 命中。** 官方实际只写「合同制员工」「本科及以上」。

✅ **验尸命令**（把 `F` 换成源稿路径，逐篇跑）：
```bash
/usr/local/bin/python3 -c "
import re,sys
t=open(sys.argv[1],encoding='utf-8').read()
P=['CET-4','CET-6','四级','六级','行测','笔试','体检','色弱','A类编制','企业年金',
   '六险二金','补充医疗','食堂','公寓','班车','落户','租房补贴','雏鹰','项目制',
   '劳务外包','第三方派遣','早投递','早投']
hit={k:t.count(k) for k in P if t.count(k)}
print(hit if hit else '✅ 无套话指纹')
# 另：'公告未披露' 计数过低 = 缺口被编造话填满了
print('公告未披露:',t.count('公告未披露'),' 待核:',t.count('待核'))
" <源稿.md>
```

🔴 **判定标准**：
| 信号 | 含义 |
|---|---|
| 指纹命中 **≥6 项** | 🔴 **整篇重写**，不要修补 |
| `公告未披露` = 0 或极少 | 🔴 官方没说的被模型脑补填满了 |
| 标题含「央企正式编」「直签」等**资格断言** | 🔴 官方只说"合同制员工"时，标题即为过度断言 |
| `source_url` 只写**门户首页** | 🔴 按红线属"无官方源"，须换成具体公告页 |

⚠️ **同批同题材必横向查**：一次写 N 篇（如同为运营商、同为国网系列），
**每篇的套话指纹要并排比对**。若多篇指纹高度重合 → 证明是同一批脑补产物，
**全部打回**。这一条比单篇检查更能抓住事故。

⚠️ **指纹不是"禁用词表"**：某单位官方**真的**写了"六险二金"，那它是硬信息、照写不误。
所以顺序永远是 **先抓官方原文 → 再回稿里查指纹**：
命中指纹**且**官方无出处 = 编造；命中指纹**且**官方有 = 合法。**不可反向操作。**

然后这样调用：

```
按 job-write 写 <期号-单位>。
硬信息只用投料单，缺口写「公告未披露」；
禁止推测、禁止引用转载号与聚合站的日期和人数。
语气参考 <最近一稿路径> 的导语与岗位表两段（只读这两段）。
写完跑 verify_draft.py，报错自己修到全绿再汇报。
```

**为什么指定"只读两段"**：给全篇会把那一稿的题材特征一起带进来；
给那两段（导语定语气、岗位表定结构）刚好够对齐，不到 300 token。

### 2.4 质控不进提示词

§八 的自检清单是**给人看的最终确认**，不要整段复制进提示词要求模型自检——
它会选择性忽略，而你还要为这段解读付费。成稿后跑脚本，让报错驱动修改：

```bash
/usr/local/bin/python3 \
  /Users/zhugx/src/skills/job-write/scripts/verify_draft.py "<稿件前缀>"
```

⚠️ **脚本有盲区**：它不比对"排版内容与源稿是否一致"。2026-09-18 曾发生 5 篇排版的
尾部被拼进别篇全文、`verify_draft` 却显示全绿。此项必须人工扫一遍：
正文讲的是本篇单位、无他单位强特征词、结尾 CTA 正常。

⚠️ **第二个盲区（2026-09-20 中信建投稿实测）**：`verify_draft` **不校验 HTML 标签配平**。
当日复用别篇 CTA 时用 `ref[idx:]` 截取，把别篇文件末尾的 `</body></html>` 带了进来，
导致根 `<section>` 被提前闭合、尾部出现游离标签——脚本仍报全绿。
**规戒**：① 复用别篇 HTML 片段时，**按标签配平截取**（计数 `<section`/`</section>`），
禁用"从锚点切到文件尾"；② 复跑质检后核对 **`<section` 与 `</section>` 数量相等**。
⚠️ **2026-09-28 实测再撞一次（国网直属单位稿）**：用"锚点 → `</body>` 前"截 `10-02-南瑞继保` 的 CTA 块，

## 四、SEO / 长尾优化（招聘类核心打法，已验证）

1. **标题必带「校招 / 2027校招」+ 单位 + 城市**（搜一搜标题权重远高于正文）。例：`江苏省铁路集团2027校招（10+15岗）`。标题 **≤64 个字符**（微信标题按字符计，不是字节——中文标题 40+ 字符很正常，实测 43 字符可正常推送），前 21 字含最强钩子。
2. **加「校招常见问答 FAQ」段（对齐微信搜一搜 Answer Box 抓取法则）**（放在"怎么报名"之后）：
   - **禁止内省式/书面化缩略提问**（如 ❌ "专业不对口有机会吗？"、❌ "能调回市区吗？"）。
   - **必须使用完整主谓宾的自然人真实搜索高频句**（含具体单位简称/岗位/意图词，便于微信搜一搜直出 Answer Box 问答精选卡片）：
     - **志愿类**：Q1 本次校招限报几个岗位？能同时投递几家二级分行/分公司？
     - **专业类**：Q2 非理工/非金融专业能报该单位的校招岗位吗？
     - **备考类**：Q3 该单位统考笔试考什么内容？行测与专业题占比多少？什么时候笔试？
     - **身体/体检类**：Q4 该单位体检有哪些硬性淘汰指标？色弱、转氨酶过高影响录用吗？
     - **工作生活/定向类**：Q5 县域支行/基层定向工作满约定年限后能调回市区吗？提供单身宿舍吗？
     - **身份与政策类**：Q6 录用后是正式合同工（正式编制）吗？往届生在择业期内算应届吗？能领南京租房补贴吗？
3. **发布后必勾合集**（如《2027年校园招聘》）做主题聚类，整栏搜权重更高。
4. **内容全程文字 / HTML（含表格）**，**绝不把岗位 / 条件做成图片**（图片不可索引，最伤搜索）。
5. **搜索/长尾与排版合规无关**：原生方言合规只影响渲染；只要内容是可索引文字，表格/section 都正常收录。真影响排名的是标题关键词、合集聚类、FAQ 问句、阅读分享等互动。
6. **SEO 摘要规范（digest，必产）**：
   - **长度**：≤120 个字符（微信 digest 硬上限）；写完必须实测字符数，超了先砍修饰语。
   - **四禁**：无 emoji（豆腐块）；无 HTML/换行；**不复述标题**（标题已展示，摘要要补增量）；不写空话（"机会难得""不容错过"）。
   - **四必含（搜一搜核心检索词密度）**：①报名**截止时间与笔试预计时点**（如"10月8日网申截止，10月底笔试"）；②1–2 个**硬门槛钩子**（人数/学历/专业限制/定向年限）；③官方**入口域名**（如 `job.icbc.com.cn`，明确官方出处）；④核心差异点（如"除科技岗外专业不限""辖内不含苏州"）。字数严控在 105~118 字符，充分利用空间且不超限。
   - **存放**：有 `-源稿.md` 的写在 h1 之后一行（**单行式，本专栏通用写法**）：
     `> **SEO 摘要**（NNN字，无 emoji）：<摘要正文>`
     两行式（`> **SEO 摘要**（NNN字，无 emoji）：` + 换行 `> <摘要正文>`）同样被支持，二选一即可。
     流水线自动提取，**日志须显示「摘要(手动) N 字符」**；无源稿的用 `--digest` 传参。
     ⚠️ **2026-09-17 修 Bug**：旧正则只认两行式，单行式会**静默回退成「摘要(自动(正文开头兜底))」**——
     写了却没用上。已修（`mp-publish/scripts/wx_pipeline.py` 支持两种写法）。**推前务必看日志那行。**
   - ⚠️ **正文里出现半角冒号不影响提取**（如 `16:00`），但**总字数必须实测 ≤120**；写 120+ 会被平台截断/回退。
     建议写成后立刻 `len()` 实测，超了先砍修饰语（泰州初稿 128 字即超限，栖霞定稿 113 字）。

## 五、排版（强制遵循微信原生方言）

必须先读 `mp-html` 技能。本流水线专用要点：
- **桌面宽屏居中约束（铁律）**：首层外包装根 `<section>` 必须显式声明 `max-width:677px; margin:0 auto; box-sizing:border-box;`。微信后台及桌面浏览器会按窗口展开，若不加 `max-width:677px; margin:0 auto;` 会撑满屏幕变成两端宽屏拉伸；加上后桌面端优雅居中，手机端自适应 100% 满屏填满。
- **色彩规范（主体 VI 优先）**：
  - 严禁千篇一律通篇通用蓝（`#1a73e8`），**正文主色调必须跟随内容主体的官方 VI 标准色**。
  - 查验路径：官网/官微/VI手册，两源一致才采。
  - 主色应用位：导语卡底/边框、章节大标题数字竖条、大表表头底色、斑马纹浅色底、FAQ 问句重点色、CTA 渐变底。（「专栏抬头卡渐变底」随抬头卡废弃，2026-09-16 起不再有）
  - 白字对比度必须达标（$\ge 4.5:1$）；功能色（截止红 `#ea4335`、通过绿 `#558b2f`、解读黄 `#78350f`）不跟 VI 走，保留语义。
  - 典型电力央企 VI 参考：中国华电（海蓝 `#0F3C88` + 天蓝 `#0070C0`）、国家电网/南瑞（国网绿 `#006747` / `#007A5E`）、国家能源集团（国能红 `#C8102E` / `#E02B20`）、中国华能（华能红 `#D9001B` + 深海蓝 `#003366`）、中国核电（中核蓝 `#004B97` + 橙 `#FF7F00`）。
- 块级容器**只用 `<section>`**，禁 `<div>`（含块级子元素会被溶解丢样式）。
- **加粗克制原则（对照搜一搜教程01）**：
  - 微信明确指出："过度使用加粗标记会让用户迷失，也不利于搜索引擎识别文章重点"。
  - **严禁整段通篇加粗、严禁列表项句句加粗**。正文每屏（约300字）内，加粗词句**严格控制在 1~2 处最具决策价值的硬核事实**（如具体人数、截止时点、关键定向年限、排他性条件）。序数词（如"1."、"2."）、过渡句一律使用正常字重。
- 禁 `position:*`；禁 `<a href>`；禁 `style` 值里写 `&#39;`。
- 首层 wrapper 只放字体属性与居中约束，**不设水平 padding**（否则与微信正文容器双重内缩，"没拉满"）。
- 校验：方言合规检查属于底层通用技能 `mp-html`，调用 `/usr/local/bin/python3 /Users/zhugx/src/skills/mp-html/scripts/wx_dialect_check.py <html>` → 必须打印 `✅ 方言校验通过`。本地成稿后推荐直接使用 `scripts/verify_draft.py` 执行三件套一体化门禁质检。
- ⚠️ 校验脚本依赖 `bs4`，用 `/usr/local/bin/python3` 跑（托管 venv 裸装版没 bs4）。

```python
from PIL import Image, ImageDraw
master = Image.open(f"{BASE}/素材/封面母版/标准社招封面母版.png").convert("RGBA")  # 900×383
logo   = Image.open(f"{BASE}/事业单位招考/素材/logos/njqxq.png").convert("RGBA")   # 380×73
LH = 42
lw = int(round(LH * logo.width / logo.height))
logo = logo.resize((lw, LH), Image.Resampling.LANCZOS)
pad_x, pad_y, radius, cap_x, cap_y = 16, 8, 10, 40, 32
cap_w, cap_h = lw + pad_x * 2, LH + pad_y * 2
layer = Image.new("RGBA", master.size, (0, 0, 0, 0))
d = ImageDraw.Draw(layer)
d.rounded_rectangle([cap_x, cap_y, cap_x + cap_w, cap_y + cap_h], radius=radius,
                    fill=(255, 255, 255, 240), outline=(220, 230, 242, 255), width=1)
layer.alpha_composite(logo, (cap_x + pad_x, cap_y + pad_y))
out = Image.alpha_composite(master, layer)
out.convert("RGB").save(OUT, "PNG")     # ⚠️ 存 RGB：RGBA PNG 推草稿时会崩（JPEG 不支持 alpha）
```

## 国网省公司系列专属红线（11- 编号段）
- ⛔ **台账里的日期/站数一律不作数**，必须回官方原文逐字重读。实例：宁夏台账写「10/7-9/28」，实际是 9/24 首场、只排 6 场、另 10 场「10月7日后适时更新」。台账只用于排期与防漏，不用于引用。
- ⚠️ **"优先招聘硕士及以上" ≠ "仅招硕士"**。公告没写招本科、也没写不招本科时，必须明写「公告未披露」，不得替官方判断。江西「少量电工类本科」是明文，宁夏不是。
- ⛔ **"未设某栏" ≠ "未披露该字段"**。行程表没有「面向院校」列时，写「官方行程表未设"面向院校"栏」，不要脑补面向范围。
- 🔧 **日期缩写禁用 `replace` 链，一律正则捕获组 + assert**。`d.replace('10月','')` 对固定月份会输出裸日号（山西 9 站全错，且源稿与正文硬信息校验都抓不到）。正确写法：`re.match(r'(\d{1,2})月(\d{1,2})日', d)`。
- 🔧 **微信服务端回读统计 `br` 必须用 `c.count('<br')`**，微信会把 `<br/>` 归一化成 `<br  />`（带两个空格），用 `c.count('<br/>')` 会误判为 0。
- ⚠️ **逐字比对前必须剥标记再归一化**：`**`、`<strong>`、`</strong>`、`>`、`「」`、en-dash `–` / em-dash `—` / 全角 `－`、弯引号。写断言时要按"成稿允许拆分加粗、允许改 dash"来写，否则全是假失败。
- ⚠️ **反向断言不能扫全文**：稿件里常有「**不要**写"优先 985/211"」这类提醒句，本身含禁用词。反向断言应针对"该词被当作事实陈述"的句型，或只扫行程/硬信息区。
- 🗑️ **草稿箱同名重复要清**：改稿重推会产生标题完全相同的第二条草稿。`wx_draft.py delete` 默认演练模式，须 `--yes` 才真删 —— **属不可逆操作，未获用户明确放行不得执行**。

### 🔴 必跑自查：源稿 ↔ 排版 关键短信息一致性（`verify_draft` 查不出）

排版与源稿是**两份独立文件**，任何批量正则改排版都可能静默丢内容而质检全绿。**每次改完排版必跑**：

```python
import re
md = re.sub(r'\*\*','', open('X-源稿.md',encoding='utf-8').read())      # 去粗体
h  = re.sub(r'<[^>]+>','', open('X-排版.html',encoding='utf-8').read())  # 去标签
KEYS = ['十份','5份','28周岁','33周岁','985','211','第20个安全年','公告未披露']  # 按稿定制
loss = [f'{k}(源{md.count(k)}/排{h.count(k)})' for k in KEYS
        if md.count(k) > h.count(k)]
print('❌ 受损:', loss) if loss else print('✅ 一致')
```

> ⚠️ **会有假阳性**：源稿 front matter 与「SEO 摘要」行的信息**不进入正文**（摘要只进 digest 字段），属正常差异。
> **判读方法**：把每个 key 的差异逐处 `print` 出上下文，确认缺失处是「摘要/front matter/推送前必做」等**非正文位置**即为正常；
> 若缺失位置在**正文段落**里 → 就是真受损，必须回滚该处。2026-09-28 吉林稿即用此法定位到"十份"被误删。

| 5 | ⚠️ **密度指标会被"排版紧凑度"扭曲**：分母是 `非空行数/40`，若 HTML 一个元素一行地紧凑输出（如生成器直接 `'\n'.join`），行数只有已发布稿的 1/3，**同样的加粗数会算出 3 倍密度** | 2026-09-28 联通稿：53 处 / 86 行 → 报 **24.65 处/屏**，而同期已发布稿青海 85 处/12.93、天津 162 处/25.61 —— **绝对加粗数比已发布稿少，密度却"超标"**。✅ 对策：在相邻标签 `><` 之间插入换行（`re.sub(r'(?<=>)(?=<)','\n',html)`）后再度量，行数即与已发布稿同量级；⛔ 该正则**只插在 `><` 之间**，绝不把标签与文字分开（否则微信端出段首空格） |

> 🔴 **文字守恒断言（强制，紧跟降加粗之后执行）**：
> ```python
> before = re.sub(r'<[^>]+>', '', html)
> for u in UNBOLD:
>     repl = COLOR_SPAN.get(u)
>     if repl is None:                    # 未登记替换色 → 只去标签，文字必须原样保留
>         repl = re.sub(r'</?strong>', '', u)
>     html = html.replace(u, repl)
> after = re.sub(r'<[^>]+>', '', html)
> assert before == after, f'降加粗导致文字丢失：前 {len(before)} 字 / 后 {len(after)} 字'
> ```
> 断言能在**写稿当场**拦下所有"静默删字"事故，成本近乎为零。移动稿重跑后净增 362 字＝全部补回的失字。
> 📌 **推广**：任何"白名单批量替换"（降加粗 / 换色 / 脱敏 / 改写）都应配同款守恒断言 —— `.get(k, '')` 这类**空串默认值**是静默删字的头号陷阱。

> 📌 **密度参考**：目标 ≤5.5 处/屏（按 40 行/屏折算）。带大表格的稿天然偏高（江西 23 行电话表 → 68 处/6.57 每屏），**表格内的数字与专名不必降**，只降引导语与整句强调。
> 📌 **该降哪些**（2026-09-28 联通稿实操定标，53 → 14 处）：**序数词**（一、／1.）**不降不行都不留**、**FAQ 问句**（`Q1 中国联通江苏校招可以投几个岗位？`——问句已是红色标题，不必再加粗）、**结构标签**（招聘对象／学历要求／投递上限…改用带色字或普通字重）、**整句强调**（"研发岗确实少""专业限制很松"）。**保留**：具体人数／岗位数／投递上限／用工性质结论／"官方未公告X"这类结论句。

### ⭐ 宣讲行程表排版规戒（2026-09-28 冀北两轮反馈确立）

- ⭐ **默认每站 3 行**：① 站点 ② 时间｜地点 ③ 面向院校（或缺失说明）。**用户明确否决过压成 1 行**（原话「还是每站 3 行啊，调整成 1 行太紧凑了」）。
- **紧凑靠行距/内边距/列宽，不靠合并行**：`line-height:1.6→1.45`、`padding:7px→5px`、日期 `10月19日→10/19`、缩减列宽、降低非重点文字字号与对比。
- ⛔ **"面向院校"列官方常缺**（江西/山西行程表根本没这列）：**不要逐站重复刷"公告未披露"**；✅ 非本省站统一写「官方行程表未设"面向院校"栏」，本省站写「本省主场，xx 同学就近参加」。
- **校验模板**：`<br/>` 数 = 站点数×2 + 链接区条数（江西 32＝14×2＋链接4）；`padding:7px` 计数须为 0；行程数据行 = 站点数。**断言要把非表格区的 br 一起算**。
- 源稿 md 与排版 HTML **必须同步改**（md 用完整日期版，HTML 用缩写版）。

### ⭐ 判断「公告未披露」是有效信息还是套话填充（2026-09-28 立规）

同一篇稿里有的「未披露」必须写、有的必须删，判据如下：

| 判定 | 条件 | 例子 |
|---|---|---|
| ⛔ **删**（套话填充） | **三项同时成立**：① 多个小问**答案同形**（全是"未披露"）；② 删掉后**读者行动不变**；③ 只是**换个说法复述上文已给的公告事实** | 「单位来头」四问框：编制/薪酬/吃住/晋升 全未披露（吉林稿） |
| ✅ **留**（有效信息） | 满足**任一条**：① 缺口**会改变读者动作**；② 指出**与他省公告的差异**（跨省系列刚需，防串稿）；③ 明确指出**本省未设某门槛**（差异化卖点） | "人数未披露→别信'招多少人'传闻"、"截止未披露→别提前订票订房"、"吉林无六级/无笔试，与浙苏不同"、"本科走一批统考" |

> 📌 **推论**：跨省系列的"公告未披露招录人数"几乎每篇都有，**这不构成删稿理由**——它有决策价值（明确告诉读者"别信传闻"），该留。真正要删的是**同形复述型**的框。
> ⚠️ **别过度校正**：删完要复跑 `verify_draft.py` + 数 `section` 配平（删框会改变嵌套计数）。

### 🔴🔴 红线：严禁把 A 单位的公告原文搬进 B 单位稿（同系列隔离纪律，2026-09-28 立规）

**事故实录**：写国网江西稿时，把天津/山西公告里的「我公司不举办任何委托的考前培训班……均与我公司无关」写进了江西稿。**江西公告根本没有这句**。句子本身完全正确，但**放错单位就是硬信息造假**——读者会以为江西官方发了这条声明。
> 📌 **注**：防骗提醒/防骗声明已于 2026-09-28 由朱总裁定**全线下线**（见 §七），此类句子不会再出现；
> 但这次事故立下的**通用红线依然成立**——跨单位连载时任何原文句子都不许搬，下面的高危清单已改用其他类型举例。

| 规则 | 说明 |
|---|---|
| ⛔ **禁搬句子** | 同系列/跨省/同集团多单位连载时，**只复用版式与组件**（表格样式、CTA、色板），**不复用任何原文句子** |
| ⛔ **引号必溯源** | 凡加「」引用官方原文，**必须逐字在本单位公告原文里 find 到**；找不到就不能写 |
| 🔥 **高危句型清单**（各版本差异极大，最易串） | ① 体检淘汰指标（恐高症／辨色力／心血管） ② 年龄口径（"不超过X岁" vs "X年7月1日及以后出生"） ③ 学历性质（统招／全日制／专升本） ④「XX优先录用」 |
| ✅ **本单位没有的字段怎么办** | **明写「本公告未披露该字段」**——不许从别省公告搬一个填上，也不许脑补。把"没有"本身变成信息（与"坏消息要直说"同理） |
| ⛔ **坏消息要直说** | 本单位没设读者关心的站点（如"本省 14 站 0 站江苏"），必须直说，不许用"可异地参加"含糊带过 |

### 🔴 「引号必溯源」要抓的三类**非原文引用**（2026-09-28 联通稿二次复查实测）

只检查"整句是否 find 到"会漏掉下面三种**看起来像原文、实际是自造**的引用：

| 形态 | 实例 | 问题 | 正确做法 |
|---|---|---|---|
| **① 合成标签** | 「任职要求—专业要求」 | 官方页里是 `【任职要求】` 下辖 `2.专业要求：`，**没有这个合成词** | 只引**真栏目名**：以岗位详情页「任职要求」栏为准 |
| **② 模板占位** | 「校园招 N 人」 | 页面实际写的是 `校园招6人`，`N` 是编者的占位符 | 要么引真实实例（「校园招6人」），要么**去掉引号**改用描述（岗位详情页标注的校园招聘人数） |
| **③ 把"问题"当"答复"** | 「可以跨专业选报岗位」被当成官方引文 | 那是官方答疑页的**问句**（"是否可以跨专业选报岗位?"），答复是"可以，各单位会根据求职者专业能力、综合素质等维度进行测试" | 问句与答复**分开标明**，或只引答复原文 |

✅ **可固化的做法（写进生成器，别靠人眼）**：在数据模块里落一张 **`OFFICIAL_QUOTES` 白名单**
（把该单位所有会被引用的原文逐字句 + 官方岗位名登记进去），然后断言：
```python
for q in set(re.findall(r'「([^」]{2,120})」', body)):
    qn = re.sub(r'\*\*', '', q).strip()        # 先剥 md 加粗标记
    assert qn in OFFICIAL_QUOTES, f'引号无出处: 「{qn}」'
```
本次即靠这条抓出「IT与技术研发」漏了"岗"字（官方岗位名是「IT与技术研发岗」）。
⚠️ **白名单要登记全**：官方岗位名动辄上百条，**从中挑出稿件真正会引用的那几条登记**即可；
未登记但确属原文的（如某个岗位名）**补登记**，不要为了过检查而改掉正确原文。

> 📌 **验收脚本模板**（每篇必跑，正反双向）：
> ```python

> # 反向：高危句必须 NOT IN
