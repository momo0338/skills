# 每日数据分析 SOP（「码上职业」专属）

> **本文件只讲「读什么、跟谁比、结论写哪、什么时候该动手」。**
> ⛔ **取数机制不在这里** —— 接口姿势、导航入口、口径陷阱一律转引 `mp-publish` SKILL **§八.3**（登录态浏览器同源 fetch 三层接口）。
> 这样拆的原因：取数是**跨账号通用工具能力**（mp-publish 同时服务满爸爱生活/码上职业），分析口径是**本号专属**。两处写同一件事＝两份会漂移的真相。

---

## 一、怎么触发

| 方式 | 说明 |
|---|---|
| **自动** | 已有每日定时任务（约 09:40）自动跑，产出日报 + 刷新「线上已发布累计表」（落点见 §五） |
| **手动（一句话）** | 「**跑今天的数据分析**」「刷新线上已发布累计表」「看看昨天那篇多少阅读」 |
| **补跑** | 说「补跑 X 月 X 日的数据分析」；接口支持按 `--date` 取历史（发表记录可翻页回溯全量） |

⏰ **为什么排在 09:40 之后**：官方规定**每天 8 点后**查前一天数据才准确；上午跑既能拿到昨天完整数据，又能顺带收进当天已发的稿。

## 二、执行五步（每步都有硬约束）

1. **探登录态**（第一道闸）
   打开 `mp.weixin.qq.com` → 读 `location.href` 取 `?token=`。
   ⛔ **取不到 token（落到登录页）就立即停**，只报告「登录态已失效，需朱总扫码」。**绝不尝试自动登录或绕验证**。

2. **拉发表记录** → `appmsgpublish` 全量（begin 步进 20，遇 380 字节空壳提前 break）。
   原始 JSON 落盘 `~/.cache/weixin/publish_records/mashang_发表记录_<YYYYMMDD_HHMM>.json`（**接口原始响应必须留档**，官方要求开发者自行缓存）。

3. **与「线上已发布累计表」对账**（防漏记）
   - ⛔ **该表原先在 `02-作战看板.md` §2.3，但看板已于 2026-09-21 删除且项目约定禁止回滚** → 表的新落点**待朱总确认**（见 §五）；**不要再往 `02-作战看板.md` 写任何东西**。
   - 线上批次数 > 表内行数 → **有未记录的新发布**，逐条补行；
   - 时刻取值：群发读 `sent_info.time`；**发表·不通知没有 `sent_info`**，读 `appmsg_info[0].line_info.send_time`（漏了会让所有不通知稿没日期）；
   - 性质：`publish_type=101` → 群发（占额度）；`=1` → 发表(不通知)；
   - 阅读/分享列 **按累计值直接覆盖**（⛔ 不是累加）。

4. **对「昨日新发」逐篇取单篇明细** → `appmsganalysis?action=detailpage`（msgid 取法见 mp-publish §八.3）。
   拿到：阅读 / 平均阅读时长 / 完读率 / 阅读渠道构成 / 读者画像（性别·年龄·地域）。

5. **出日报**（见 §三）+ 落盘（见 §五）。

## 三、日报固定四段（这就是交付物，别写第五段）

1. **昨日新发**：篇名 ｜ 性质 ｜ 阅读 ｜ 分享 ｜ 完读率 ｜ 搜一搜占比 ｜ 一句判断（强 / 中 / 弱）
2. **位次变化**：全站阅读排行谁进前 3、谁掉队（**看位次，不看绝对值** —— 累计值每天在涨，绝对值不可比）
3. **异常**：阅读显著低于同类 / 漏记的发布 / **登录态是否临近失效**
4. **选题建议**：哪个关键词连续走强 → 是否值得加一篇；哪个题材做多了没量 → 是否降级为素材池

## 四、行动阈值（有观察就必须有动作，避免"只看不动"）

| 观察到的现象 | 应采取的动作 |
|---|---|
| 连续 2 天阅读 < 同类中位数 **50%** | **先查标题关键词有没有搜索量** —— 本号是搜索驱动，低量九成是词的问题，不是内容问题 |
| 某关键词**连出 2 篇进前 3** | 考虑立**子系列**（国网、银行、事业编的先例）；先按 `planning.md` 评估搜索需求量 |
| 完读率 **> 40%** 且 搜一搜 **> 75%** | 读者精准度高 → 同主题**再分层**（拆解 / 清单 / 避坑 / 对比）持续吃词 |
| 搜一搜占比**跌破 60%** | 流量结构变了（可能掺入推荐流量）→ **重估选题口径**，别照旧押搜索词 |
| 累计关注**连续 3 天 0 新增** | 查 CTA 与文末引导：是否缺「关注钩子」，或 CTA 被排版污染 |
| 某篇阅读正常但**留言/在看为 0** | 属正常（小号），**不要**为凑互动去加引导，会伤阅读体验 |

## 六、红线（与项目纪律一致）

1. **阅读只认 `appmsgpublish` 的累计口径**；后台「内容分析」单篇页是**区间口径且可能滞后**，**只用于渠道构成与读者画像**，不用于比大小。
2. **数据是累计值** ⇒ 日报里的「当日增量」＝ 今日累计 − 昨日累计，**得自己相减**（接口不给日增）。
3. **不擅自改主档**：数据分析**不改** `ijob/data/jobs.db` 的硬信息（截止日/人数/状态）。分析只反哺**选题**。
4. **粉丝量小，用户属性页可能返回空**（实测 117 字节）→ 属正常，**不要反复重试**。
5. **账号是个人订阅号**：datacube 21 接口全 48001，直连还偶发 `40164`（出口 IP 白名单）→ **一律走登录态浏览器**，别浪费轮次去调 `wx_stats.py`。
6. **ego-browser 用完即关**：`completeTaskSpace(name, { keep: false })`。
