# job-bulletin-write · 官方公告重排引擎

> **定位（朱总裁定）**：凡有正式公告长文的招聘线，弃用 job-write 的 8 段解读骨架，改用
> **「原文重排骨架」**——公告原文一字不改，只做拆段与关键数字加粗；AI 的增值件收缩为四样：
> 划重点、三宫格、岗位表（附件提取）、FAQ。真实成稿样例见 `references/samples/`。

---

## 一、骨架（固定七件，顺序不可换）

| # | 件 | 内容来源 | 纪律 |
|---|---|---|---|
| 1 | **码上君划重点** | 从公告提炼 3-5 条 | 每条一个钩子；编制/用工性质必须有一条如实交代 |
| 2 | **数据三宫格** | 截止 / 性质 / 规模 | 用 layout_kit.quad_grid 传 3 格 |
| 3 | **岗位表** | 官方附件逐行核 | 岗位数、人数加总必须等于公告总数（守恒） |
| 4 | **公告原文全文** | 公告原文照录 | ⛔ 一字不改；只做拆段、关键数字加粗、长条款转小字注脚 |
| 5 | **常见问答** | 从公告提炼 6-8 问 | 完整主谓宾自然问句（对齐搜一搜 Answer Box） |
| 6 | **CTA** | `素材/组件/cta-客服码单码.html` | layout_kit.cta() 自动替换品牌色 |
| 7 | （来源小字） | 原文尾部 | 附件说明＋落款＋原文链接 |

**砍掉不写的**（相对旧 8 段）：单位来头原创段、码上君解读黄底卡（内容并入 FAQ）、
资格禁入重写卡（原文条件节已覆盖）、实操建议。

## 二、流程（十步）

```bash
# ① 拉公告原文：先 WebFetch；被拦(Bad Request/412)→curl 带浏览器 UA 直拉
# ② 查重：emit_briefing --state-audit + ls */待发布/ | grep <单位专名>（按单位专名，禁标题匹配）
# ③ 没写过→补台账：/tmp 备份总表 xlsx → 招聘信息 sheet 加行（单脚本一次读一次写+断言+重读校验）
# ④ 投料单：emit_briefing "<单位>"（[miss] 时按脚本指引走补台账路径）
# ⑤ 附件逐行核（守恒：人数加总=公告总数）——按格式选工具：
#    .xlsx→openpyxl；旧版 .xls→xlrd（openpyxl 不认）；.pdf→pdfplumber；
#    岗位表以「页面图片」内嵌的（正文无附件链接时 grep 页面 <img>）→下载 png 后多模态直接读表；
#    附件直下返回 HTML=防盗链 → curl 加 -e "<公告页URL>" Referer 重下；
#    合并单元格以 extract_text 版面序复原，别漏行
# ⑥ 填 data/*.json → 生成排版（内建断言见 §五、JSON 壳见 §3.2）：
python3 ~/src/skills/bulletin-write/scripts/gen_bulletin_json.py data/<file_stem>.json
# ⑦ 封面：build_cover.py --type 社招；无干净官方 logo → 纯母版不加胶囊（⛔ 不自制底版）
#    （工作目录不在公告页时，--out 用绝对路径）
# ⑧ 推送：wx_pipeline.py --profile mashang --html ... --cover ... --source-url ... --digest "手动摘要≤120字"
#    ⛔ 本骨架的 HTML 无 SEO 摘要块，--digest 必须显式给（gen 结束时会打印 DIGEST），否则落到自动兜底
#    ⛔ 推送前先 `wx_draft.py list --count 5` 复核草稿箱：同一条链接可能有多路会话并行处理，
#      db `drafts` 查重只反映推送前的状态，对推送窗口内别人刚推的稿子完全无感
#      （2026-11-11 江西省港口集团稿：查重三表全 0 通过，push 后发现草稿箱已有同名稿，只能删自己那篇）
# ⑨ 回填：emit_briefing --mark "<单位>" --to draft --facts "..."；总表该行 内容状态→draft
#    ⛔ --facts 必须是 KEY=VALUE 分号连接（如「岗位=15岗23人；报名=10-16 17:00截止」），纯叙述文本会被拒；
#      总表检索词用单位全名子串（注意「经开区」匹配不到「经济开发区」这类简称/全称差异）
# ⑩ 排期：按报名截止升序报朱总定夺；窗口冲突时 ⛔ AI 不自作主张砍稿（多稿同窗=人工取舍）
```

## 三、config 编写规范（每篇唯一要写的东西）

**新稿写纯数据 JSON**：复制 `scripts/data/_schema_example.json` 填空，生成用 `python3 scripts/gen_bulletin_json.py data/<file_stem>.json`（详见 §3.2）。
真实成稿样例在 `scripts/data/*.json`（共 70 篇历史稿，可直接参照/改 `_ws` 复用）。以下字段语义 py 配置与 JSON 完全一致。

- `TITLE`：≤64 字，前 21 字带钩子（单位+人数/亮点）；
- `DIGEST`：≤120 字单行，含截止时间、硬门槛、入口（域名/地点/电话）；
- `HIGHLIGHT`：dict(sub, intro, items, numbers)；
- `GRID`：3 个 (大字, 小字) 元组；
- `POSITION_TABLE`：dict(title, note, headers, rows, widths, footnote) 或 None；
  - 附件岗位 ≤15 行 → 逐岗位列表；
  - **>15 行 → 分单位汇总表**（岗位数/人数/用人方式/学历构成/报名邮箱）+亮点注脚，明细回指官网附件；
- `ORIGINAL`：list of (节标题或 None, [段…])；段用 `("p", 文本)` / `("note", 小字)` / `("sub", 小节标题)` / `("url", 明文网址卡)`；
  原文文本一律照抄，只许在关键数字外面包 `<strong>`；节标题用原文编号（一、二、三…），不添加自拟后缀；
- `FAQ`：[(问, 答)] 6-8 条；
- `SOURCE_NOTE`：附件+落款+原文链接小字；
- 可选：`BRAND`/`BRAND_DARK`（品牌色覆盖）、`ALLOWLIST`（指纹豁免）、`SOURCE_MD`（同步产出源稿）、`DATE`/`SOURCE_URL`。

### 3.1 EXTRA_SECTIONS（2026-10-12 三峡集团31家单位卡立）

`POSITION_TABLE` 只支持单表。需插入**多个自定义区块**（如按单位分卡展开）时，
config 定义 `EXTRA_SECTIONS = [(分区标题, [(kind, 内容), ...]), ...]`，
渲染在「公告原文」之前、FAQ 之后的位置之外（即原文前）：
kind 支持 `raw`（原样插入，调用方自备合法 layout_kit 片段）／`p`/`note`/`sub`/`url`。
⛔ `EXTRA_SECTIONS` 内容**同进编造指纹/自证句/比较级机检**（新增代码已接），
官方简介/附件原文里的比较级与福利词须进 `ALLOWLIST` 并注明出处。
⛔ 未定义 `EXTRA_SECTIONS` 时行为与改造前**逐字一致**（已用阜宁/宝应两稿 diff 回归验证）。

| 坑 | 症状 | 防御 |
|---|---|---|
| 用 `s.index('<标题>')` 切段算屏数 | CTA 后的 base64 客服码图（58KB）被当正文，屏数虚高 3 倍 | 算篇幅先 `re.sub(r'base64,[A-Za-z0-9+/=]+','<IMG>',s)` 再量 |
| 自定义卡片用默认色 | 与正文色板打架（两套蓝） | config 配 `BRAND`/`BRAND_DARK`，取主体 logo 众数色 |
| 单位卡与总览表内容重复 | 同一数据渲染两遍，篇幅翻倍 | 二选一；或总览表只留速查列并标「见下/见后」 |
| `write_source_md` 不认新字段 | 源稿 md 缺新区块，三件套不同步 | 改造 `write_source_md` 一并渲染 `EXTRA_SECTIONS` |

### 3.2 JSON 壳工作流（数据/样板分离，2026-11-11 全量迁移落定）

新稿**写纯数据 JSON**，不再写 py 样板代码（历史 70 篇 py cfg 已全量迁移为 `data/*.json` 并删除）。主入口：

```bash
# 主方式（纯数据 JSON，70 篇历史稿均在 scripts/data/）
python3 scripts/gen_bulletin_json.py data/<file_stem>.json
# 兜底：gen_bulletin.py 仍在（供 gen_bulletin_json 内部调用 / 应急 py cfg）
python3 scripts/gen_bulletin.py <config.py 路径>
```

- `scripts/bulletin_spec.py`：壳模块，从 JSON 构造 gen_bulletin 可消费的 cfg 对象（补 WS/OUT/SOURCE_MD 路径、Layout、默认品牌色、渲染 `layouts` 里的表格、`_notes`→核查履历）。
- `scripts/gen_bulletin_json.py`：薄封装，`gen_bulletin.py` 未改一行，断言语义与之一致。
- `scripts/data/_schema_example.json`：字段 schema 示例，新稿照此填空。
- 表格：`layouts` 里每个表存 `{"__html__": "<原样 layout_kit 片段>"}` 最稳（**字节级零风险**）；确知与主 Layout 同主题色时也可存 `{"headers":[...],"rows":[...],"widths":[...]}` 由壳重新渲染。⚠️ 部分老稿用了**独立主题色 Layout**（如烟草 BG_TABLE 斑马纹 #F2F7FD），改结构化重渲染会变色——故一律内联原 HTML 为默认。
- **`_notes`**：原 py cfg 头部 docstring 的硬信息核查履历，搬家进 JSON 的 `_notes` 字段，不丢。

**迁移工具**（历史 70 篇 py cfg 已全量转 data/*.json）：
- `scripts/cfg2json.py`：单篇 py cfg → JSON（`python3 cfg2json.py cfg_xxx.py out.json`）。
- `scripts/batch_migrate.py`：批量迁移 + **字节级校验**（`--write` 才落盘；dry-run 默认）。迁移后必须 `TOTAL n | OK n | MISMATCH 0`。
- 迁移纪律：转换后逐篇比对 `gen_bulletin.build(cfg)` vs `build(bulletin_spec.load_spec(json))` **字节完全一致**才落盘；有外部数据依赖（读 /tmp 临时文件）的老稿若数据不可重建则删除（2026-11-11 删安徽选调北大、甘肃选调两篇死稿）。
- **2026-11-11 已完成全量迁移：70 篇 py cfg 已转 data/*.json 并删除。** `cfg2json.py`/`batch_migrate.py` 保留作历史归档工具（日后若再有 py cfg 可复转）。日常写稿只用 JSON。

## 四、硬纪律（红线，违者打回）

1. **原文一字不改**：只拆段、加粗、长条款转小字。改写=回退到解读稿模式，⛔；
2. **硬信息只认公告原文与官方附件**：人数加总守恒；缺口写「公告未披露」；
   **编制属性原文没写就写「公告未披露/签订劳动合同」**，严禁脑补「进编」（原文写了「劳动合同或派遣」就直说无编制）；
3. **岗位表必须守恒**：行数×人数加总=公告总数，不符=停笔查附件；
4. **来源声明**：划重点 intro 末尾必须带「码上职业仅做排版整理，未改动原文表述」；
5. 出口固定 `--profile mashang`；`wx_draft.py` 默认 manba，漏写=事故；
6. **三件套质检口径**：`job-write/scripts/verify_draft.py` 按 8 段骨架指纹校验，**不适用于本骨架**——
   质量门禁＝`gen_bulletin.py` 内建断言（原文守恒/指纹/比较级/自证句/section 配平/空 span）
   ＋推送链路的 `wx_dialect_check`＋draft/get 五项验收；
7. **写划重点/摘要禁用「最多/最高…之一」类词**——有原文依据也换成数值区间表述（机检会拦）；
8. **同系列多批次隔离**：每条划重点、FAQ 答案必须回**本批次**公告 find 溯源，严禁凭上一批记忆搬。

## 五、机检与坑位

**gen_bulletin.py 内建断言**（写盘前逐条过，命中即失败）：
原文守恒（ORIGINAL 原样出现在成品）／编造话术指纹（指纹词命中 TITLE+DIGEST+划重点+三宫格+岗位表+FAQ
但不在 ORIGINAL 原文）／A 类自证句／无据比较级／section 配平／禁空 span·div·th·position／`<title>` 在位／DIGEST ≤120。

| 坑 | 症状 | 防御 |
|---|---|---|
| `layout_kit.table` headers 传元组列表 | 表头渲染成 `('序号','8%')` 字面量 | headers 传纯文本列表，widths 单独传（其 docstring 写反了，以实现为准） |
| `layout_kit.doc_open` 参数不带 `<title>` 标签 | 流水线报「未能提取到文章标题」 | doc_open('`<title>`…`</title>`') |
| quad_grid 外层 td 无 border:0 | 微信渲染出矩形框线套住圆角卡 | layout_kit 已修（border-collapse:collapse＋td border:0） |
| 本骨架 HTML 无 SEO 摘要块 | 摘要落「自动(正文开头兜底)」 | 推送必带 `--digest` |
| gov 附件下载回 HTML | openpyxl BadZipFile | curl 加 `-e <公告页URL>` Referer |
| 机关线巡检报告投料单 [miss] | parse_patrol_report 列序与机关线报告不符（待修） | 按「补台账→重跑投料单」路径绕过 |
| 岗位表以页面图片内嵌 | 附件列表里找不到简介表 → 误判「无岗位明细」 | 正文无附件链接时 grep 页面 `<img>`，下载 png 后多模态直读 |
| 旧版 .xls | openpyxl BadZipFile | `xlrd`（venv 已装） |
| **「扫码领取附件」是草料/短链活码**（如 `qr61.cn/xxx/yyy`） | curl 只拿到 SPA 空壳（约 10KB，正文 0 行）；内置浏览器打开是 iPhone mockup **静态图**——文件列表是图片不是 DOM，`dom_cua_get_visible_dom` 只返回「PC小程序打开／关闭 Markdown」两个按钮，截图又超 10MiB 上限。2026-11-11 江西省港口集团稿在此耗掉 12 轮仍一无所获，被迫出「无岗位表」的降级稿 | **用 ego-browser 打开活码页，取 `document.body.innerText`（是 Markdown），其中 `ncstatic.clewm.net` 的链接就是 4 个附件的 PDF/docx 直链**，下载后 pdfplumber / openpyxl 解析 ⇒ 一步到位拿到完整岗位表。⛔ 别猜 API、别反复截图 |
| **`*.pzhl.net` 人事考试平台公告页**（普众互联系，安徽/多省国企常用） | ①用 utf-8 读全是乱码（`ʡͨعɼ޹˾`）；②按行 split 会把「10.2」「亿元」「（一）报名。」拆成独立行，段落支离破碎、易漏条款 | ①页面是 **GBK**：`raw.decode('gbk')`；②正文按 **`<P[^>]*>(.*?)</P>`** 正则切段、去 `<SPAN>` 后即得完整段落（比按行切干净得多）；③页内 `href` 常**直接给出岗位表 PDF 直链**（`img2026.pzhl.net/exampzhlnet/年月/xxx.pdf`），pdfplumber 一次提全表。2026-11-11 安徽通航稿据此拿到 9 岗 9 人 |
| **来源小字写完却没出现在成品里** | `gen_bulletin` 的顶层 `SOURCE_NOTE` 只进源稿 md 与机检参考集，**不渲染进 HTML**——源稿 md 里看得到、HTML 产物里搜不到 | 把来源小字作为 `('note', …)` 追加到 `ORIGINAL` **最后一节的 blocks 末尾**（参照 `data/2026-10-13-2027国考公告-公告重排.json`：末节 `None` ＋ note「国家公务员局　2026年10月」）。⚠️ 已连栽两次（2026-11-11 江西港口、同日安徽通航），出稿前必须 grep 成品确认关键串在位 |
| **海报印的网址打不开** | 2026-11 已连中两例：内蒙古能源集团猎聘网址 404（正确为 `wow` 非 `www`、项目号少一位）；安徽通航 `ahgxzc.pzhl.net` 404（正确为 `ahgzcz`，xzc↔zcz 印反） | 一切入口**以公告正文与二维码解出的地址为准**，海报印刷件一律 curl 实测；不一致时在划重点、来源小字、FAQ 三处如实披露，`source_url` 用公告页 |
| `--facts` 非 KEY=VALUE | `--mark` 报 facts_invalid，状态没回填 | facts 用「岗位=…；报名=…」分号连接格式 |
| **改完标题直接重推** | 草稿箱多出一篇同名稿（`--update-auto` 查重对改后标题失效） | 迭代稿一律 `wx_pipeline.py --update-media-id <旧 media_id>` 原位更新，禁裸推 |
| **FAQ 问句写「是正式编制吗？」** | gen_bulletin 指纹词机检拦（`正式编制` 在 FINGERPRINTS，原文无此词） | 改问「是编制还是合同制？」（单用「编制」放行，且贴真实搜索句） |
| **搜一搜想查却查不到** | 只用全称、只用「校招」，漏掉变体 | 见 §八：校招/秋招、全称/简称分散覆盖 |

| **长串溢出（`wx_overflow_check` 报 +2/+3px）** | 全角括号「（）」按 CJK 规则禁止行首/行尾，浏览器不拆 ⇒ 长专业名撑破窄列。⛔ **缩字号（11.5→11→10.5px）、调列宽都只会让溢出在 320↔360↔414↔677 之间挪动，治不了标**（实测连试 4 轮白费） | 治根＝**可见文本一字不改、全角括号前插 `<wbr>`**（`esc_zwsp()`，只影响断行不影响字符）；配合专业列加到 44-52% |
| **每岗一张表 → 篇幅爆炸** | 206 岗 × 2 表 = 412 张 `<table>`，标签开销翻倍（实测表格占正文 91%、431 屏） | 改**每单位 2 张表**：表A 岗位/城市/学历/人数、表B 岗位/专业/地点/其他（两表按岗位名对齐）⇒ 表格 62 张、篇幅 319 屏 |
| 两张表各带一个 `<section>` | 引擎 `section 配平失败` 断言 | 只让最后一张表带 `</section>` 包裹 |
| 窄列里塞长串（CJK 表格） | td 必须同时给 `word-break:break-word` + `line-break:anywhere`，否则中文长串溢出 | 单位卡/岗位表 td 统一带这两个属性 |

| **人数标签写死 categoryId** | 三个通道的「招聘人数」**categoryId 各不相同**（统招 365／基石 363／专项 361），写死 ID 会让基石专项人数全解析成 None（稿里误写"人数未逐岗标注"）。实测踩过一次 | 解析时**按 `category.name=='招聘人数'` 动态取 children 建字典**，绝不写死 id |
| `write_source_md` 的 raw 占位文案写死「31 家单位卡片」 | 复用该引擎的其他稿源稿 md 里出现"31 家"（基石只有 10 家、专项 8 家） | 占位文案改通用「此处为单位卡片排版」；改引擎后必须用既有两稿 diff 回归 |
| 划重点写「招人最多」被比较级机检拦 | 三通道里统招 742 > 专项 192，"最多"站不住 | 换成可核实的相对表述（「学历门槛最低」＋列另两通道门槛），⛔ 不靠豁免蒙混 |

## 六、验收清单（推送后）

1. `[VERIFY] ✅ draft/get` 五项绿（标题/正文/容器/空样式/图片URL）；
2. `wx_draft.py get --media-id ... --json` 回读 `digest` 非「自动兜底」；
3. `--profile mashang` 日志首行确认；
4. **`wx_draft.py list` 确认同名稿只有 1 篇**（`--update-auto` 查重失败会**静默造重复稿**）；
5. 状态回填：db `drafts` 表（`draft_ctl` hook 自动 INSERT/UPDATE；`content_ctl` 报 `no such column: media_id` 属 schema 漂移，不影响 draft_ctl 真源）＋总表该行 内容状态→draft；
6. 群发后当天归档（git mv 进 `已发布/`）＋台账/状态推 published。

## 七、写作纪律（填 data/*.json 时的人工检查项）

| 纪律 | 要点 |
|---|---|
| **B 类无据推测** | FAQ 答案只写公告说的；后果类判断（「逾期视为放弃」）必须能在原文 find 到 |
| **C 类官腔套话** | 划重点提炼时跳过文化理念/薪酬口号，只留可核实事实 |
| **「引号必溯源」** | 「」引用的内容须在本单位公告原文 find 得到 |
| **加粗密度 ≤5.5 处/屏** | 原文重排只加粗关键数字天然低密度；删加粗只能逐条白名单，禁按字数阈值批量删 |
| **主色取主体 logo 众数色** | config `BRAND/BRAND_DARK` 覆盖；拿不到 logo 用默认 B 线蓝，禁沿用上一篇色板 |
| **「公告未披露」是信息还是填充** | FAQ 若连续几问答完读者行动不变 → 删问；但编制/薪酬缺口**必须**如实写「公告未披露」 |
| **推送前自检** | title≤64 前 21 字钩子／明文 URL break-all／页脚四无（来源行/免责/预告/防骗）／封面 RGB PNG／source-url 指官方源 |

> ❌ **明确不在本技能范围**：招聘站 SPA/接口抓取（智联/51job/银行招聘站）——那是 job-write 管 A 线的武器；
> 本线是政府官网静态公告页。

## 八、SEO / 长尾优化（2026-10-11 苏州农商银行稿实测立）

> 打法继承 `job-write` §四（标题带校招＋问句 FAQ＋合集聚类＋全文字可索引），本节只记**公告重排骨架的独有坑**：
> 本骨架**没有 SEO 摘要块**，DIGEST 全靠 config 手写——写歪了没人兜底。

### 8.1 标题：前 21 字是黄金位，非搜索词不许占位

- 硬上限 **≤64 字符**（按字符计，非字节），实测 40 字符很安全。
- **前 21 字必须装下「单位 + 届别 + 人数 + 最强钩子」**——列表页/分享卡片只露这一段。
- ⛔ **岗位类别缩写不配占黄金位**。反例：`营销通用30席专业不限`（前 21 字被截成「…：营销通用3」，
  「营销通用」不是搜索词，白占最贵位置，「专业不限」被切在外面）。
  ✅ 正例：`苏州农商银行2027校招40人：专业不限30席、往届可报，10月24日12点截止`。
- **钩子优先级**（搜一搜实测竞品标题词频）：`专业不限` > `应往届可报/往届可报` > `网申倒计时（精确到点）`
  > `笔试考情`。带上「12点」这类竞品懒得写的精确时间，本身就是差异化。

### 8.2 摘要（DIGEST）：手写，四禁 + 四必含

| 四禁 | 无 emoji（豆腐块）／无 HTML 换行／**⛔ 不复述标题**／不写空话（"机会难得""不容错过"） |
|---|---|
| 四必含 | ①截止与笔试时点 ②1–2 个硬门槛钩子 ③官方入口域名 ④核心差异点 |

- ⛔ **最常见错误＝把标题整句抄进摘要开头**（标题已展示，摘要要补增量）。
- 摘要应装标题**装不下**的四类东西：
  **上级大词**（如「江苏农商行系统统招」——单篇能蹭到全省大词的流量）／
  **同义变体**（「秋招」，竞品高频但项目规范用「校招」）／
  **单位简称**（用户搜「苏州农商行」，规范标题写全称「苏州农商银行」）／
  **独家硬信息**（如「限 2 个志愿」）。
- 长度 **105–118 字符**（上限 120，别顶格）；写完 `len()` 实测，超了先砍修饰语。
- 推送必带 `--digest`，并盯日志 `[0] 摘要(手动) N 字符`——出现「自动(正文开头兜底)」= 没取到，停下修。

### 8.3 FAQ：贴搜索句，但先过机检

- 用**完整主谓宾的自然搜索句**（对齐搜一搜 Answer Box），禁止内省式缩略提问（❌「专业不对口有机会吗？」）。
- ⛔ 写前先确认问句不含 `FINGERPRINTS` 指纹词：`正式编制`／`直签`／`落户`／`食堂`…命中且原文无出处＝断言失败。
  折中写法：贴搜索习惯又不撞指纹的等价表述（「编制还是合同制」「用工性质」）。
- **优先挑读者真会搜、且原文能支撑的困惑**。例：报名入口是全省统招专题时，
  「XX校招和XX系统统招是同一场吗？」是本篇最高价值长尾（原文「全省岗位中选择2个志愿」可支撑），
  价值远高于「两个工作地点有什么区别」这类内部结构问题。

### 8.4 平台侧（发布时人工做）

1. **必勾合集**（如《2027年校园招聘》）——整栏聚类权重远高于单篇；
2. 内容全程文字/HTML（表格照样收录），**绝不把岗位表做成图片**（图片不可索引）；
3. 公告重排＝整理非原创，**不声明原创**，来源声明写在划重点 intro 末尾；
4. `source-url` 指官方原文，阅读原文可跳转；
5. 改标题后**必须 `--update-media-id` 原位更新**，直接推＝多一篇重复草稿。
