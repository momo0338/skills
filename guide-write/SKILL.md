# Guide-Write: 通用实体场馆与景区攻略采写规范 (v1.1)

## 一、概述与核心定位

本技能专为**实体点位与场馆攻略类图文**打造通用采写引擎。不再受限于单一题材，通用化覆盖：
- **公共文博**：综合博物馆、历史遗址馆、行业科技馆、艺术美术馆、名人纪念馆；
- **自然人文**：城市公园、国家湿地、风景名胜区、古镇老街、历史文化街区；
- **研学教育**：大学历史校区、科学实验基地、天文台、国防/工业研学基地；
- **亲子休闲**：室内游乐、特色探店、主题乐园、近郊徒步；
- **民生政策与盘点**：健康疫苗、全省/全市特色榜单盘点。

> **解耦原则**：
> 本技能聚焦于**“写什么、怎么写、怎么排雷、怎么改写、怎么自检”**的内容与叙事层。
> 排版样式统一遵循 `mp-html` 原生方言规范，草稿推送全链路交由 `mp-publish` 自动执行。

## 二、Step 0：动手写稿前双重审计（形成肌肉记忆）

### 0.1 📸 EXIF 实拍日期批量审计（严防导入日误写陷阱）
- **血泪教训**：照片文件名中的日期（如 `image-20260513xxxx`）往往是**手机照片批量导入电脑的日期**，绝非现场实拍日！以此写图注和导语会导致系统性时间穿越。
- **强制动作**：动笔写图注与导语前，必须先调用脚本拉取真实拍摄时间戳（`DateTimeOriginal`）：
  ```bash
  python3 scripts/exif_inspector.py <文章图片素材目录>
  ```
- **口径判定**：
  - 有 EXIF：严格按照实际拍摄日（如"4月18日实拍"）写入图注；
  - 无 EXIF（网图、翻拍资料图）：图注公式必须明确标注图源（如"· 图源：学校官微"）。
- **图片压缩规范**：实拍素材过大时，使用系统命令压缩：`sips -s formatOptions 62 -Z 1100 <图片>`。

### 0.2 🔍 爆款对标与“长尾三问”反哺（ChatGPT / Codex 必须强制前置执行）

> 🚨 **【执行铁律 · 强门禁】如果在 ChatGPT 或 Codex 下执行采写任务，动笔前必须强制执行以下三项，严禁跳步：**
> 1. **运行检索命令**：
>    python3 /Users/zhugx/.workbuddy/skills/mp-search/scripts/mp_search.py search "<核心关键词>" -s hot -n 5
>    python3 /Users/zhugx/.workbuddy/skills/mp-search/scripts/mp_search.py search "<核心关键词>" -s new -n 5
> 2. **提炼并明确汇报**：向用户输出对标分析简报，明确说明：最热篇套路/痛点、最新动向、正文必须反哺的独家增量；
> 3. **严禁跳过检索直接写正文或直接拿旧稿交差**。未完成此步骤禁止进入正文撰写与排版环节。
- **检索范围与数据归档（强制 Top 5 + Top 5）**：
  - 动笔前必须调用 `mp-search` 完整检索同类关键词的**最热 Top 5** 与 **最新 Top 5** 文章。
  - **清单与数据就地归档**：必须将检索得到的两组完整数据表格（含序号、完整标题、公众号、发布日期、阅读量、点赞、分享、收藏、评论与链接）**直接保存在正文 Markdown 中，严格放置在「SEO 摘要」之前**。
  - **专属隔离标识**：必须使用 `<!-- benchmark:start -->` 与 `<!-- benchmark:end -->`（外层套 `<details><summary>📊 微信搜一搜爆款对标数据（最热 Top 5 + 最新 Top 5 备查，排版忽略）</summary>...</details>`）将其包裹隔离。排版工具（如 `wx_prep_content.py`）在解析 HTML 或推送微信草稿时自动忽略该注释块，保证内部备查数据不丢失，同时绝不污染线上正文。
- **强制回答长尾三问并反哺到正文**：
  1. **痛点反差钩子是什么**？（读者痛斥什么商业套路？如"别只逛假特产街"、"别只知道XX，这处被低估的5A"）；
  2. **官方最新时效变动是什么**？（近期有无免票利好、预约政策变动、宠物友好新规？）；
  3. **具象奇观与核心体验是什么**？（现场最具视觉冲击力、不可替代的王炸展项或特色体验是什么？如810米挂壁栈道、真火车驾驶模拟舱、2.2亿年化石、巨型无动力攀爬等。文博历史类若契合课本典故可作为加分项，严禁对自然/公园/游乐类生搬硬套教材）。

### 0.3 🧯 对标通道不可用时的合规替代方案（2026-09-16 实测补充）

**现实**：`mp-search` 的两条通道在部分环境会**同时失效**——① 微信端内搜一搜依赖微信桌面端，ChatGPT / Antigravity 之外调不通；
② 搜狗降级通道（`opencli weixin search`）会 **TIMEOUT**（exit 69 / 75，`OPENCLI_BROWSER_COMMAND_TIMEOUT` 调大也无效）。
**此时 Step 0.2 的硬门禁不能靠"跳过"来解决**，改用下面这个**更强**的替代口径，并在正文对标块里**如实写明降级原因**：

1. **本号后台「发表记录」做同题材对标（首选替代）**：取同类题材历史稿的真实 **阅读 / 分享 / 在看 / 留言**，
   比第三方搜狗数据的可信度高得多，且**题材可比性更强**。取数走 `mp-publish` §八.1 的后台内部接口。
   ```bash
   PY=/Users/zhugx/.workbuddy/binaries/python/envs/default/bin/python3
   $PY "/Users/zhugx/codeup/obsidian/03-工作记录/满爸爱生活/工具/发表记录勾稽.py" --index   # 含阅读/分享/在看/留言
   ```
   实测价值：2026-09 写南师大标本馆稿时查到**本号 2025 年同题材稿 6850 阅读 / 537 分享，是攻略类历史分享最高**，
   而**转载官方通知那篇只有 483 阅读**——直接推出"读者不买搬运通知的账，要的是去过的人的信息增量"这条写作策略。
2. **公开检索补套路**：`WebSearch` 捞官方稿（官网/官微/官媒）与同类攻略，看**选题角度覆盖面**，
   在正文对标块里列成「来源 / 日期 / 套路观察」表，并明确标注**无互动数据**。
3. **对标块仍要写**，但把「渠道说明」放在最前面，写清"哪条通道失效、失效原因、替代来源、因此缺少哪些指标"。
   **宁可写明降级，也不要伪造互动数据，更不要因为取不到数据就跳过对标。**

### 0.4 ♻️ 旧稿无本地实拍素材？从本号历史已发稿里捞回来（2026-09-16 实测）

**场景**：要写一个以前写过的点位（复访/换角度），但 vault 里没有实拍图——`assets/` 里只有尺寸规整的网图（如 1200×675、600×450，**无 EXIF**），
说明是当时从网上下的，不是自己的照片。

**解法：从本号自己的历史已发文章里把配图取回来**（那些才是真·实拍）：

```js
// ego-browser：打开 mp.weixin.qq.com/s/<旧稿短链>，取正文图（微信懒加载在 data-src 上）
const imgs = await js(String.raw`[...document.querySelectorAll('#js_content img')]
  .map(i=>i.getAttribute('data-src')||i.getAttribute('src')||'').filter(Boolean)`)
```
- 下载**必须带 Referer**，否则 mmbiz CDN 防盗链：`curl -e "https://mp.weixin.qq.com/" -o out.bin "<url>"`
- 旧稿 URL 从《已发文章索引》或后台发表记录 JSON 的 `content_url` 取。
- **文档里自述的拍摄日就是最可靠的图注日期**：旧稿正文若写了"本文内容拍摄于2025年9月14日"，
  图注照此写 `· 2025年9月14日实拍`；比翻 EXIF 更快且同样有据。
- 本号图片常带 `公众号 · 满爸爱生活` 水印，属自有素材，可正常使用。
- 若旧稿图片顺序与段落交错，**按段落主题对位命名**（`点位名-视角.jpg`），别照搬序号。

> **反面教训**：本次一开始去南师大官网、生科院官网、扬子晚报抓图，结果分别遇到"图片已被清理只剩 base64 占位"
> "图片带第三方媒体水印""图集里混入相关推荐文章图（无法确认归属）"。**绕一圈不如先回自己号里翻。**
> 顺序应为：**本号历史稿 → 官方源 → 媒体转载（须标图源）**，且无法确认归属的图一律不用。

## 三、通用点位攻略“五步标准骨架”

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. 导语区：真实生活桥段开场 + 情绪动机 + 意外发现 + 首张全景实拍 │  ──> 原生引言框排版
├─────────────────────────────────────────────────────────────────┤
│ 2. 📋 核心概览 + ⚠️ 游玩避坑提醒 (五要素直连无冒号)           │  ──> 承接门票、交通与避坑
├─────────────────────────────────────────────────────────────────┤
│ 3. 场馆深度干货：分展项图文 + 纯中文 + 每段加粗≤1处 + 数字不加粗 │  ──> 删去所有自嗨与下判断废话
├─────────────────────────────────────────────────────────────────┤
│ 4. 动线与顺路联动：同片区/同交通线顺路串联 (拒绝流水账分时卡)    │  ──> 替读者规划周边
├─────────────────────────────────────────────────────────────────┤
│ 5. 💡 冷知识区：3-4 条有反差、有出处的考据点                    │  ──> 知识增量与情感升华
└─────────────────────────────────────────────────────────────────┘
```

### 1. 导语区（生活化实录腔）
- **开头用真实桥段**：一个带情绪的同行者/孩子动机（谁闹着要做什么、说走就走）→ "结果意外发现：…"。不写"上周末/某日计划去 X 逛，结果…"的流水账，禁用"上周末"等模糊相对时间。
- **对话直给式**：一律「满宝：xxx」「满爸：xxx」，**零叙述引导词**（不写"满宝进门就问"、"听完说了句"）。
- **人设纪律**：AI 未知的生活细节（小名、具体事件、孩子原话）**严禁擅自编造**，必须留占位请用户确认。
- **开篇桥段必须限定在实拍图能证实的场景**（"图内/图外区分"红线）：图外场景（窗外、隔壁景区、山顶）若无对应实拍图，直接删除桥段，宁缺勿编。
- **排版要求**：导语区优先使用原生「引言框」组件（竖条纹背景 + 右上角标签）。

### 2. 📋 核心概览 + ⚠️ 游玩避坑
紧随导语与首图之后、正文攻略第二段之前（先用故事拉进场景，再给避坑准备）：
- **概览要素**（emoji+短语）：
  - 🎫 门票：免费（预约口径一句带过），或者门票价格，以及南京游园卡，江苏旅游年卡，江宁旅游联卡等哪些卡可用
  - 📍 地址：xxx（一句定位，含商圈/地标锚点）
  - 🚇 交通：地铁哪个线哪个站、自驾导航停车哪里
  - ⏰ 时间：周二至周日 9:00-17:00（**周一闭馆**，加粗给关键时间）
  - 🌿 时长：2-3小时（实测：约1.5小时没玩够）
  - 🏅 亮点：A · B · C
  - 🏷 标签：什么级别的文物保护单位，多少 A 级景区，金陵 48 景的哪个，几级博物馆等相关标签

- **避坑提醒**：只写硬核实测口径（如现场预约是否可行、限时清场时段、停车位紧张程度）。

### 3. 场馆深度攻略（语言与加粗纪律）
- **纯中文表达**：不用英文或网络黑话（如"drinking game"→"抽签游戏"）。
- **加粗 ≤ 1 处/段**：只加最硬的信息（时间规则、关键展项名、强推荐人群）。**数字绝对不加粗**（2具、126字、216件，数字自带冲击力）。
- **去自嗨与下判断**：删去所有"这个选址很友好"、"比蹭导游还过瘾"、"非常震撼"的主观判断句。只留事实、实测与硬规则。
- **图注规范**：公式为`主体描述 · 日期实拍`，日期取 EXIF；非自摄图必须标`· 图源：xxx`。严禁写操作细节防图文不符，不加▲符号。
- **正文严禁携带标题区**：badge-row、h1、meta 绝不能进 HTML 正文 body！标题全由 push 脚本的 `--title` 参数注入。

### 4. 动线与顺路联动
- **拒绝分时流水账**：不写"9:00-10:00干嘛、10:00-11:00干嘛"的分时卡（单馆容易凑字数、对读者价值弱）。
- **顺路联动**：改给"同片区步行5-10分钟顺路点"或"同地铁线路前后站联动点"。

### 5. 满爸冷知识
- 每篇保留 3-4 条有反差、有考据的历史/科技冷知识，独立成段，增加完读价值。

### 6. 文末增长与转化闭环（严禁在正文放置行政味「信息核实说明」）
- **坚决弃用冷冰冰的「信息核实说明」**：读者读完正文处于情绪峰值，文末若放一段类似免责声明或质检清单的行政式文字，会瞬间浇灭情绪，严重拉低完读体验。核实细节留存内部备查，**正文末尾统一采用「增长转化闭环」**。
- **标准化三层转化结构**：
  1. **走心共鸣升华（写在最后）**：用 1~2 段家长视角大实话，点透“带娃来这里的深层人文/成长价值”，赋予读者转发家长群、朋友圈的心理账户；
  2. **三向强行动召唤（CTA）**：
     - 💬 **留言互动（低门槛开放式提问）**：抛出具体选项（如“文中这几处老建筑你最想去哪座？”、“你家娃课本上学过XX吗？”），直接撬动评论区；
     - 📌 **收藏与转发（实用工具属性）**：点出“限约1次/名额紧张/避坑刚需”，引导“先收藏备查，转发班级群/家委会组团出游”；
     - ❤️ **点赞与在看**：结合号主人设与真诚产出自然引导支持。
  3. **往期精选矩阵（2~3 篇强相关连读）**：以标准超链接卡片推荐同片区、同题材或同深度的高质量文章，制造连环阅读，拉长公众号停留时长。

## 四、大流量标题与长尾 SEO 公式

### 1. 标题长尾大流量公式
```
[出发/地域卖点]！[目的地/反差钩子]：[关键词1]、[关键词2]、[关键词3]
```
- **严禁缺失地域根词**：标题必须带"南京遛娃"、"南京自驾1小时"、"南京周边"等明确地域词，截流自然搜索大盘；
- **拒绝文艺自嗨，锚定用户搜索意图**：不用"倒影/春山"等低频虚词，改用"古代高考"、"千字文号舍"、"810米挂壁栈道"等具象奇观与高频意图词；
- **借势顶流反差**：如"别只逛假特产步行街"、"别只知道燕子矶"；
- **前 21 字原则**：**标题总字符 ≤ 64**，且**前 21 字**（微信分享卡片完全露出范围）必须展示最强钩子！
- **标题四处必须严格一致**：MD frontmatter `title` == MD `# H1` == HTML `<title>` == 推送命令 `--title`。

### 2. 正文长尾 SEO 搜索意图四项覆盖
1. **人文研学类课本/典故赋能（非文博类绝不强套）**：若点位涉及历史人物、文博遗产，可自然关联统编语文/历史教材篇目（如范进中举、李白望天门山、《拉贝日记》等），将普通打卡升维为研学刚需；自然公园、户外休闲、探店游乐类则侧重具象奇观与硬核玩法，严禁无中生有硬编教材考点；
2. **高频痛点场景词覆盖**：明确点出"室内/雨天/避暑/避寒/夏日避晒"等痛点场景；
3. **理清通票与子景点关系**：一句话化解搜索用户的购票疑虑（如"50元通票包含南北两馆"）；
4. **长尾 SEO 摘要规范（≤120字红线，无 emoji）**：
   - 骨架：`地域交通 -> 场馆全称及包含关系 -> 费用与优待 -> 差异化看点 -> 实用词（动线/联刷）`。

### 3. 深度故事挖掘与动态标题策略（拒绝刻板套模板）
- **严禁机械套用死板分类**：标题绝非公式填空（“综合版/教材版/反常识版”仅作思路启发，严禁变成固化的流水线套路）。标题的爆发力永远源于**正文最硬、最独特的故事内核与戏剧张力**。
- **深度挖掘正文独家故事/反常识角度**：动笔拟标题前，必须重新审视全文，提炼出 3~4 个最具震撼力或心理共鸣的故事切口：
  1. **冷门硬核细节切口**：如“北大楼墙砖刻着六百年前工匠名字”、“拆明故宫旧砖建大学”；
  2. **命运与人物张力切口**：如“两代建筑师跨越半个世纪的守护：父亲建难民所、儿子建纪念馆”；
  3. **家国血性/反常识奇观切口**：如“比钟楼还高3米的40米爱国旗杆”、“一个校园里叠压两处独立全国重点文保”；
  4. **大盘生活反差切口**：打破常规打卡心智（如“别只挤先锋书店/玄武湖，穿过马路摸真古迹”）。
- **结合爆款机制给出「最佳推荐 + 差异化备选」**：
  - **给出 1 个综合最优的主推标题**（兼顾搜索长尾、故事钩子与点击欲望）；
  - **同时提供 2~3 个基于不同故事角度挖掘的备选方案**；
  - **逐一说明**：每个方案挖掘了正文哪段独家故事、为什么能打动特定读者、前 21 字露出分析（微信卡片不被截断）与受众画像。
- **必须包含长尾 SEO 摘要说明**：每次交付正文时，文首必须附带 ≤120 字、0 emoji 的长尾 SEO 摘要，注明字数与骨架五要素（地域交通 -> 场馆全称及包含关系 -> 费用优待 -> 差异化看点 -> 实用动线词）。

## 五、「去 AI 味」六条自查标准（真人感核心）

1. **评价型小标题 → 改为具体信息型**：
   - ❌ "含金量极高"、"怎么玩最值"、"一文看懂"
   - ✅ "过江那几分钟"、"江北这几站，出站就是农田"
2. **同一信息只在最强位置说一次**：
   - AI 极爱在导语、小标题、正文中各强调一次同一卖点。钩子位（标题/导语）保留，正文换成推进性事实。
3. **删去所有总起过渡句**：
   - ❌ "玩法很简单：…"、"先说结论：…"、"值得注意的是…"、"推开民国历史画卷…"
   - ✅ 整句直接删掉，把干货内容直接顶上来。
4. **书面词口语化**：
   - "我们坐到的是桥林新城站" → "我们那天就坐到桥林新城站"；"该站周边" → "站外"；"游客可在此" → "在这儿"。
5. **加入 1~2 句克制的实话（大实话）**：
   - 真人会降温、会吐槽（"不为了去哪儿，就是为了坐车"、"站台修得跟市区一样宽，就是空"、"不过，也不要期望太高"）。AI 写不出这种大实话，这恰恰是真人感的第一来源。
6. **组件细节对齐人设**：
   - 概览卡 emoji 要贴切（地铁票价用 💰 不用 🎫）；加粗只给硬信息，每段 ≤1 处。

## 六、严格的事实核查与防伪纪律（红线）

1. **两源官方交叉**：所有门票、闭馆时间、展期、史实参数，必须经官方渠道（官网、管委会、官微、地方志）核实。
2. **外观描写防伪（重中之重）**：
   - 描述建筑外观材质、构件形制、植物景观（红砖/青砖、藤蔓、锯齿顶、古井位置），**必须由自有实拍放大或官方文字核对**，严禁轻信第三方自媒体描写！
   - 自查动作：吸收任何一句外观描写前，先问"这句有没有官方源？有没有实拍图？"，都没有则直接删除。
3. **实拍素材归属核查顺序**：
   - ① **图内实物文字**（门牌、碑刻、牌匾，必须单图放大核验）；
   - ② 与官方建筑图对比柱式、屋顶、台阶形制；
   - ③ 官方文字描述。
   - 素材归档统一命名为`点位名-视角.jpg`（如`东南大学-健雄院.jpg`），严禁使用景物或氛围词命名。
4. **外部稿件 ABC 分拣法**（他人稿件吸收原则）：
   - **A 类（直接吸收）**：官方源可证实的年代、人物、构件名、地名由来等信息增量，并入正文；
   - **B 类（需用户确认）**：亲历桥段、当天见闻，默认不吸收，确认真实后按原话保留，不润色成 AI 腔；
   - **C 类（一律不采）**：查不到出处的"专业细节"、自夸形容词、绝对化用语，坚决弃用并在汇报中说明。

## 七、文体变体骨架

### 1. 无实拍多点位盘点类（如散装江苏/全省盘点）
- **由头式导语**：点明盘点由头（"最近把某某翻了一遍，发现一个很有意思的现象…"），不硬编家庭桥段；
- **逐条目字段化**：严格区分"现用官方口径"与"早年网络流传"，后者标注"非官方"；
- **全景对照表**：用 Markdown 斑马纹表格做全景对照，便于截图与二次传播；
- **冷知识+情感收尾**：3-4 条有梗考据，结尾回到地域情感共鸣与一句互动提问。

### 2. 健康科普与民生政策类（如疫苗/开学政策/医保）
- **骨架**：免责声明 → 引言框导语 → 📋 速览卡 → 分节决策干货 → 家长最常问 Q&A → 💡 冷知识 → 📌 信息核实说明。
- **决策链前置**：读者先要"怎么办"再要"为什么"。第一部分收拢完整决策链（变化→时间→剂次→去哪打→多少钱）；第二部分再展开原理与疑问。
- **铁律**：某个疑问一旦扩写为独立小节，必须从 Q&A 里删掉，严禁同一内容出现两次。

### 3. 小红书图文笔记转化规范（同一素材双平台分发）
- **标题 ≤ 20 字**：公式为`城市+品类｜最强看点`（15-17字最佳，钩子前置）；
- **避开绝对化用语防机审**："全国唯一/最强/最好"改写为陈述句，防止被小红书机器审核限流；
- **前 50 字抓人**：滑屏浏览无铺垫，开头直接上画面感；
- **标签三层配比**：大标签（泛领域） + 中标签（城市/品类） + 精准长尾标签；
- **制图规格**：3:4 竖图（1242×1656），主标题落在 0.098H 避开顶部渐变，PIL 渲染避免使用无法支持的 emoji 豆腐块。

## 八、封面设计铁律（微信/小红书通用）

> **配色总则（VI 优先）**：正文卡片的主色应尽量取自**内容主体的官方 VI/标准色**——不限高校，博物馆、景区、品牌、城市文旅皆然；查不到再回到本号默认色板。功能色（警示红、提示黄）不跟 VI 走。

1. **彻底弃用纯色大字 PPT 封面**（用户原话："非常难看，严禁生成"）。
2. **封面来源优先级（2026-09-16 朱总明确立规）——有图用文中图，无图才生成**：
   - **① 文中有图（默认路径）**：直接**从正文配图里选**做封面，**不要调用 ImageGen**。
     - 实操：`wx_prep_content.py` 本来就会自动选"最宽横图"裁封面——这条默认行为现在就是**首选路径**，不是兜底。
     - 若自动选中的不是文章主形象图（历史教训：阳山碑材稿它选了戏楼广场，弱化了主题），按 §十 的等比放大居中法手动裁，
       或 push 时 `--cover` 显式指定。
     - 从横图裁 **900×383（2.35:1）**；若只有竖图（手机实拍 3:4 / 9:16），裁中段主体带，
       **主体必须落在中心 383×383（1:1）安全区竖条内**（微信次条/分享卡抓取中心，否则主体被裁切）。
     - 注意：**裁出来如果只是"人海/局部特写/无明显主体"，宁可换一张，也不要硬凑**——封面要一眼能认出"这是哪、有什么"。
   - **② 文中无图 / 无可用横图（兜底路径）**：才调用 ImageGen 生成。
     - 原创扁平矢量 / 卡通插画，主体为地标建筑（如中山陵、南京眼、琉璃塔、明城墙）或文章核心意象，暖色 cheerful。
     - **注意成本**：ImageGen 每张约 5–10 credits，生成前须在回复里向用户披露。
   - **③ 共同红线（两条路径都适用）**：
     - **画面中严禁带任何文字**：微信后台会把文章标题以灰白半透明浮层强行压印在封面下部（占高度 45%~65%），封面写字必然与标题浮层打架。
     - 若选中的文中图本身**带第三方媒体水印**（荔枝新闻/扬子晚报等），**不要用它做封面**，换自摄图或走 ② 生成——第三方水印出现在封面是最难看的一种。
     - 尺寸 **900×383（2.35:1）**；所有视觉主体落在中心 383×383 安全区。
3. **一句话记忆**：`有图 → 挑文中最好的一张裁；无图 → 才 AI 生成`。AI 生成从"默认"降级为"兜底"。

## 十、常见坑速查手册

| 坑位现象 | 根本原因 | 标准解决方案 |
|---|---|---|
| **图注全写错为同一天** | 把文件名导入日（如 `20260513`）误当拍摄日 | 动笔前必跑 `exif_inspector.py`，读 `DateTimeOriginal` |
| **封面文字被微信浮层遮挡** | 微信后台强行压印标题浮层占下部 45%~65% | 封面一律用 **AI 插画无字纯图**，绝不在图上写字 |
| **封面次条被裁切** | 未考虑微信分享和次条抓取中心 1:1 (383×383) | 视觉核心元素必须收拢在画面水平中心 383px 竖条内 |
| **正文推送后多出大标题** | HTML 正文开头自带了 badge-row/h1 标题区 | 生产脚本中就不要写标题区，标题全由 `--title` 提供 |
| **样式在手机端丢失/溶解** | 使用了 `<div>` 块级嵌套或 `position` 定位 | 全局只用 `<section>` 容器，零 position，遵循 `mp-html` |
| **重推草稿箱产生两个同名稿** | 未清理旧草稿 media_id | 使用 `--delete-old-media-id` 参数调取自动清理 |
| **无头截图文字/表格被裁** | `--window-size` 不改 layout viewport（恒 500px） | 用 JS 探针读 `scrollWidth`，或设 `.page` 临时 `width:375px` |
| **长表格正文横向溢出** | 表格未设固定布局被内容撑破 | 强制 `table-layout:fixed` + 各列内联百分比宽度 |
| **外观描写被抓包失真** | 盲目采信第三方自媒体的红砖/青砖/藤蔓形容词 | 第三方外观修饰一律清零，只信自有实拍放大与官方文字 |
| **概览卡标签列被压成竖排**（"门/票"两行） | `<table>` 用默认 auto 布局，值列内容长时浏览器把窄标签列压到只剩一字宽 | 概览卡表格**一律** `table-layout:fixed` + 百分比列宽（emoji 9% / 标签 17% / 值 74%），标签列加 `white-space:nowrap`。**2026-09-16 东南大学稿已翻车（已群发无法回改），南师大稿修复** |
| **配色想贴内容主体的官方 VI** | **不限高校**——高校、博物馆、景区、乐园、品牌、城市文旅，凡主体有官方 VI/标准色就先查再配色，瞎猜会跑偏 | ① 查证途径：官网/官微/百科/校史馆/品牌手册，**两源一致**才采；② 主色只用于表头/标题/强调条，白字对比度要够（≥4.5:1，不够就加深）；③ 功能色（避坑红、提示黄）不跟 VI 走，保留语义；④ 已知样本：**南京师范大学 = 绿色「南师绿」**（校徽标准色，寓意教育/生命/活力；金陵女子大学 1919 年校色为紫色）→ 深绿 #1B5E20 表头、#2E7D32 强调条、#F3F8F4 斑马纹、#DCE7DD 边框 |
