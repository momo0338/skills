# patrol-to-publish · 巡检到发布的固定流水线

**人机分工（本技能的硬边界）**：

| 阶段 | 谁做 | 说明 |
|---|---|---|
| 巡检 | 脚本 | 复用 `巡检记录/*.py` 四线，本技能**不重写采集逻辑** |
| 解析/去重/分派 | **AI** | `today` 子命令，产出待办 + 候选池 |
| **核验硬信息、决定写哪几条** | **人** | ⛔ AI 不得自行开写；硬信息只认官方公告原文 |
| 成稿 | AI | 走 `school-write` / `hospital-write` / `job-write` 分派结果 |
| 推草稿箱 | AI | `wx_pipeline.py --profile mashang --html <排版.html>` |
| **群发** | **人** | ⛔ 公众号后台人工点，AI 不做 |
| 核验发表记录 | AI | `verify`，判据＝后台「发表记录」，⛔ 草稿箱不是判据 |
| 状态回填 | AI | `mark` / `sync`，每次写前自动 `/tmp` 备份 |
| 归档 | AI | `archive`，`git mv` 三件套进 `已发布/` |

## 用法

```bash
PY=~/.workbuddy/binaries/python/envs/default/bin/python3   # ⛔ 必须 venv，系统 python3 无 openpyxl/PIL
S=~/src/skills/patrol-to-publish/scripts/patrol_to_publish.py

$PY $S today                    # ⛔ 每天巡检后第一步：生成待办 + 候选池
$PY $S today --line gov         # 只看某条线
$PY $S sync --dry-run           # 巡检条目播种进 内容状态.json（unwritten）
$PY $S sync                     # 真播种
$PY $S mark "<单位专名>" --to written --file "<排版.html>"
$PY $S audit                    # 四方对账
$PY $S verify "<单位专名>"      # 核验是否已发布
$PY $S archive "<单位专名>"     # 归档三件套进 已发布/
```

产物固定落位（工作区内）：

```
运营/流水线/YYYY-MM-DD/01-今日待办.md     ← 人核这份
运营/流水线/YYYY-MM-DD/02-候选池.json     ← 全量结构化，供二次筛选
运营/流水线/待办.md                        ← 当期看板（指向上面两份）
```

## 🔴 实测坑位（2026-09-30 全部踩过并已修）

### 1. 概览表措辞四线各不相同 ⇒ 正则写死必静默返回 None
```
机关 | **真·开启公告池（主口径，含已过期/待核，见下行分解）** | **277 条** |
电力 | **在架招聘公告（真·开启，主口径）** | **654 条**（跨源去重后；剔除重复 2508 条）
铁路 | **在架招聘公告（真·开启）**            | **26 条** |   ← 无「主口径」三字
银行 | **在架招聘公告（真·开启，主口径）** | **36 条** |
分层行同样不齐：机关「长期（长期/招满即止类表述）」，铁路「长期」光秃秃无括号
```
⇒ 解法＝**逐行扫前 60 行按关键词定位**（`_read_claims`），⛔ 不要写「按固定括号内容」的正则。
四线全 None 过一次，不报错、不告警。

### 2. 表头列数不统一 ⇒ 必须动态列映射
机关/银行 7 列（日期|报名截止|状态|来源|监测源|热度|标题），电力/铁路 **4 列**（无来源/监测源/热度）。
把列数写死 → 三条线解析成 0 条且**不报错**。
⇒ 按表头名建 `colmap`，⛔ 不按下标。

### 3. 跨源去重只按 URL = 假阴性
实测 69 条在架条目 **URL 零重复**（同一条公告被 2 个监测源各印，URL 完全不同），
只按 URL 去重得 0。归一化标题后有 **4 组**真重复（无锡滨湖区卫健委 / 吴江教育 / 吴江卫健 / 南京市机关事务局）。
⇒ **双键**：`URL 命中` 或 `招聘主体 + 归一化标题` 命中。⛔ 光按标题也不够（同名公告可能属不同批次）。
去重必须排在排除判定**之前**。

### 4. 「监测源」是转载方，不是招聘主体
江苏省人社厅监测源下 8 条全是高校稿（南京工程学院/扬州大学/泰州学院/南信大/特师…）。
拿监测源去搜本地稿件 → 8 条全假命中"已写过"。
⇒ 主体必须**从标题抽**（`extract_subject`），分派/已写判定/去重/状态匹配全用主体。

### 5. `re.split(词表, ...)` 会把 `|` 当正则分支
`_SUBJ_STOP = "公告|简章|通知|…"` 直接 `re.split` ⇒ 整个词表变成一个字符类，
「江苏海洋大学」被切坏，**9/9 用例全错且输出是词表字面量本身**。
⇒ `"|".join(re.escape(w) for w in 词表.split("|"))` 先拼 alternation。

### 6. 「出现过」不足以判「写过」
三个实测假阳性：
- 江苏海洋大学 → 命中扬州大学稿里的**串稿检测排除清单**
- 扬州大学 → 命中盐城三院稿里的「扬州大学临床医学院」
- 中国电力 → 命中国电南自稿里的「中国电力二次设备」

⇒ 判真写过必须命中**结构位**（文件名 / 正文行首 / 单位署名），散文提及只记 weak。
`written_check` 返回 `{strong, weak}`，⛔ 只有 strong 才排除。

### 7. 巡检把往年公告判成「长期」留在在架层（巡检侧 bug，本技能不擅改）
电力线实测：国网技术学院分公司 2022/2023/2023/2024 四条 + 国网国际发展 2018~2025 共 15 条，
报名截止列全是「—」（正文未取到）却被判「长期」；同站 2021~2025 相似条目却正确落在「待核」。
违反红线「抽不到截止≠长期，只能判待核」。
⇒ 流水线侧独立设防 `STALE_AFTER_DAYS = 300`：发布日距今超 300 天一律不作为当天写稿候选，并注明疑似巡检分层 bug。
**改巡检脚本须另走流程**（`/tmp` 备份 → 改 → 全量重跑 → 核对守恒自检行）。

### 8. 聚合伪单位
监测源自报「国网全部单位」，每条公告主体不同（黑龙江/天津/宁夏电力），拿聚合名无法定位公告与网申入口。
⇒ `is_fake_agg()` 标记排除，主体留在 `subject` 字段供人工判断。

### 9. 守恒自检必须校两层
① 分层加总 == 主口径；② **「三」章节实际渲染条数 == 有效 + 长期**。
⛔ 只校① 会漏掉「报告说 36 条在架、实际只渲染 20 条」这种渲染层 bug。

### 10. `audit` 第 3 项曾大面积假警报
原实现用「专名在正文出现过」判稿件存在 → 40 published / 45 written 报出几十条不一致，
实测稿件都在 `待发布/`（只是标题被微信为打开率改写）。改强命中后降到 **16 条，且经抽查全为真警报**
（稿确实不在磁盘，即 `2aa5de1b` 清理时删了未归档那个根因）。
