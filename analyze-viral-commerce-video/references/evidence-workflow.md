## 1. 输入确认

优先使用完整本地视频和同作品元数据。短链接、作品 ID 或分享口令先通过对应下载技能取得：

- 作品 ID 与规范链接一致；
- 本地文件是可解码 MP4；
- 时长、尺寸、文件大小和 SHA-256 已记录；
- 元数据与视频来自同一作品。

只有截图或平台阶段时，可以分析已有证据，但不得声称完整观看。

## 2. 自动证据包

对本地视频运行：

```bash
python3 scripts/prepare_video_evidence.py /absolute/video.mp4 --output-dir /absolute/analysis
```

需要自动转写时追加：

```bash
--asr-model base --language zh
```

脚本应生成：

- `media-info.json`：音视频流、时长、帧率和尺寸；
- `frames/`：按固定间隔抽取的帧；
- `contact-sheet.jpg`：带时间戳联络表；
- `scene-changes.json`：硬切候选时间；
- `audio-diagnostics.json`：音轨与音量统计；
- `asr-raw.json`：可选的原始转写；
- `evidence-manifest.json`：文件哈希、工具状态和限制；
- `deliverables/`：正式 Markdown 和 UTF-8 JSON 骨架。

提供 `--metadata` 时，脚本必须在其中找到 `role=video` 且 SHA-256 与输入视频一致的本地资源；不一致时停止，不能把另一作品的身份和指标绑定到当前视频。

同一输出目录只有在视频哈希、运行参数、清单状态和全部必需文件都一致时才可复用。相同视频的 `partial` 或缺文件证据包应在隔离临时目录中重建，成功后事务替换；哈希不一致或没有可验证清单的非空目录不得覆盖。

清单状态：

- `complete`：媒体探测、抽帧、联络表、场景检测和音频诊断完成；显式请求 ASR 时 ASR 也完成。
- `partial`：非核心组件失败，例如场景检测、音量诊断或显式请求的 ASR 未完成；脚本返回码为 `2`。
- 核心步骤异常：不发布临时证据包，保留原正式目录，脚本返回码为 `1`。

## 3. 时间与画面复核

- 完整播放至少一次，联络表只用于定位。
- 默认 0.5 秒抽帧时，段落边界写为“约”；需要精确剪辑点时改用逐帧或更密抽帧。
- 场景检测只提供候选。人工区分硬切、闪光、遮挡、快速推拉和大面积物体运动。
- 混剪视频先建立素材模块，再拆创意阶段。
- 联络表必须显示时间戳；生成失败时保留逐帧文件并在报告中说明。

## 4. 音频复核

音频诊断只能说明是否有音轨、平均/峰值音量等技术事实。完整报告还要实际听取并记录：

- 人声数量与主要说话人；
- 语速、停顿、重音、情绪和可懂度；
- 背景音乐是否存在、强弱和作用；
- 音效位置与作用；
- 口播、字幕、动作是否同步。

未完整听取时写“仅检测音轨”或“抽样听取”，不要推断音乐和音效。

## 5. 字幕与转写

将文字覆盖分为四种：

1. `人工逐帧核字`：按字幕变化检查全部可见文字；
2. `系统化全量 OCR 并复核`：全部字幕区间经过 OCR 和人工纠错；
3. `抽样 OCR`：只检查部分帧；
4. `未检查`。

ASR 只生成口播初稿。数字、等级、品牌、成分、材料产地、价格和功效词必须结合原音与画面字幕复核。原始 JSON 留在 `evidence/`。

## 6. 正式交付

- `breakdown.md`：读者友好的中文报告；
- `transcript-reviewed.md`：需要逐字稿时提供；
- `breakdown.json`：符合 `assets/breakdown.schema.json`，使用 UTF-8 直接中文；
- 报告列出依赖、证据覆盖、时间精度和限制。

使用 `python3 -m json.tool` 检查 JSON 语法，并人工确认中文没有变成不可读转义。

## 7. 失败处理

- `ffprobe/ffmpeg` 不可用：停止自动证据准备，报告依赖缺失，不发布临时证据包。
- 元数据视频哈希不匹配：停止并要求正确元数据，不以文件名或作品标题猜测匹配。
- 联络表失败：保留单帧，修复后重跑；不得删除原视频。
- Whisper 不可用：将 ASR 状态写为 `unavailable`，继续视觉分析。
- 场景检测无结果：不等于没有转场，仍需完整播放。
- 下载失败：保留输入、错误和尝试路径；不把失败解释为作品不存在。
