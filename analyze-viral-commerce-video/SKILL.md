# 带货视频证据化结构拆解

先准确还原视频，再解释传播与转化机制，最后给出可复用决策。不要跳过事实层直接输出营销总结。

## 使用说明

### 支持输入

- 本地视频、抖音等公开链接或用户提供的分享口令；
- 视频截图、封面、字幕、口播稿或平台生成的拆解；
- 抖店等已登录后台中的榜单、指标和“爆款解析”；
- 多条商家/达人样本，用于横向比较和共性提炼。

### 默认执行流程

1. 确认输入来源和可访问证据。
2. 输入不是本地视频时，先按“明确 ID/链接入口”取得并校验本地视频与元数据。
3. 使用 `scripts/prepare_video_evidence.py` 建立隔离的证据包。
4. 完整检查视频、音频、字幕、元数据和带时间戳联络表。
5. 对混剪、多人、多场景或重复脚本视频先建立素材模块图。
6. 完成画面、景别、机位、主体、动作、场景、口播、卖点、细节和转场拆解。
7. 对数字、等级、材质、功效、健康、安全和价格宣称建立宣称证据矩阵。
8. 再分析停留、理解、证明、信任、节奏和转化机制。
9. 最后区分可直接采用、有条件采用、不建议采用，并给出原创改编和单变量验证方案。

### 默认交付物

- 一份经复核的中文 Markdown 结构化拆解报告；
- 清楚标注已查看、未查看、平台提供和推断内容；
- 对长视频或混剪视频提供素材模块图；
- 将采用建议和原视频事实分开呈现。

### 可选交付物

- 经复核的 Markdown/SRT 转写稿；
- 可读的 UTF-8 结构化 JSON；
- 抽帧联系表、字幕证据或媒体探测结果；
- 多视频对比表、评分、脚本公式或改编镜头表。

### 文件与证据约定

默认使用以下目录，不把原始机器输出混入正式交付：

```text
analysis/
├── evidence/
│   ├── media-info.json
│   ├── frames/
│   ├── contact-sheet.jpg
│   ├── scene-changes.json
│   ├── audio-diagnostics.json
│   ├── asr-raw.json
│   └── evidence-manifest.json
└── deliverables/
    ├── breakdown.md
    ├── transcript-reviewed.md
    └── breakdown.json
```

- 将原始 ASR、OCR、场景检测日志和模型内部字段放入 `evidence/`，不直接作为用户交付物。
- 将复核后的报告、转写稿和结构化 JSON 放入 `deliverables/`。
- 中文 JSON 使用 UTF-8 和直接中文字符，禁止把 `\uXXXX` 转义或模型 token/logit 当成可读报告。
- JSON 使用 [assets/breakdown.schema.json](assets/breakdown.schema.json) 的稳定字段与证据状态。

### 结论边界

- 没有榜单或表现数据时，不把视频直接称为“爆款”。
- 没有点击、成交或 GMV 时，不用点赞等互动数据推断销量。
- 平台分析、自动转写和视觉推断必须与直接观察分开。
- 复用表达机制，不复制原视频素材、台词、音乐、布景或表演。

## 明确 ID、短链接和分享口令入口

输入不是本地视频时，不要先做截图式分析：

1. 从分享口令提取 `https://v.douyin.com/.../`；明确作品 ID 保留原值，不猜测或改写。
2. 调用 `$dy-cli` 的明确 ID/短链接下载路径，要求同时保存视频和元数据。
3. 下载后核对作品 ID、规范链接、文件数量、MP4 容器、时长、尺寸、文件大小和 SHA-256。
4. 只有完整本地视频通过校验后，运行证据准备脚本并开始完整拆解。
5. 下载失败时保留原始输入与错误，切换该下载技能规定的登录态或解析兜底；不得把“解析失败”写成“作品不存在”。

如果用户只要求基于已有截图或后台阶段分析，可以继续，但必须将视频、音频、完整字幕和精确时间标为未取得。

### 调用示例

- “拆解这个视频。”
- “按抖店爆款解析结构分析这条挂车视频。”
- “比较商家榜和达人榜各 10 条视频。”
- “把这条视频的画面、景别、机位、动作、卖点和转场拆清楚。”
- “根据这条视频给我一版原创改编镜头表。”

## 选择和操作来源

1. 优先使用用户放入任务范围的来源。
2. 用户指向当前已打开的桌面应用或已登录后台时，使用 Computer Use 直接操作该应用；除非用户要求，不切换到另一套浏览器登录。
3. 用户提供本地视频时，使用适合的媒体工具检查时长、画面、音频、转写和可见文字。
4. 只有截图、转写稿或平台分析时，明确哪些证据无法查看，不得声称完整观看了视频。
5. 后台分析默认保持只读。未经用户明确要求，不点击脚本生成、发布或店铺设置等有状态操作。

## 记录证据过程

解释创意前，记录：

- 使用的源文件、链接、后台页面、截图、转写和元数据；
- 使用的媒体探测、抽帧、场景检测、ASR、OCR 或平台分析工具；
- 哪些材料是机器原始输出，哪些已经复核；
- 缺失证据和实质限制。

只有本地视频或历史校准基线时，不得暗示使用了当前视频的抖店官方拆解。

将原始 ASR JSON、模型 token、logit、OCR 原始输出和场景检测日志视为内部证据。引用中文前先解码和复核；无法确定的词句标为不确定，不得自行补写。

### 准备本地视频证据

运行：

```bash
python3 scripts/prepare_video_evidence.py /absolute/video.mp4 --output-dir /absolute/analysis
```

默认生成媒体信息、0.5 秒带时间戳抽帧、联络表、场景变化候选、音量诊断、文件哈希、证据清单和正式交付骨架。可用 `--asr-model base` 运行 Whisper；不可用时在清单中记录 `unavailable`，不要静默假装已转写。

脚本输出是检查入口，不是最终结论：

- 提供元数据时，必须通过本地视频 SHA-256 一致性校验，不能只凭文件名或路径关联；
- 仅复用视频哈希、参数、`complete` 状态和必需文件全部一致的证据包；
- 所有新证据先写入隔离临时目录，完成后事务发布；中断或核心错误不得污染正式目录；
- 清单为 `partial` 或脚本返回码为 `2` 时，先处理失败组件，不得当作完整证据包；
- 联络表用于定位，不能替代完整观看；
- 场景变化是候选，必须人工确认硬切、动作遮挡和闪光；
- 音量统计不能识别音乐、音效、说话人或语气，必须实际听音频；
- 自动转写不能替代字幕核字。

首次执行后读取 [references/evidence-workflow.md](references/evidence-workflow.md) 了解精度与失败处理。

## 建立证据边界

在分析中区分：

- **直接观察**：从视频、音频或画面中直接看到或听到；
- **平台提供**：平台显示的指标、标签或分析；
- **分析推断**：根据证据判断其可能产生的用户反应或转化作用。

不得虚构未看到的台词、指标、时间、商品属性或因果效果。榜单和指标区间只是当前快照，不代表某一创意选择必然导致表现。

对文字覆盖标记：

- `人工逐帧核字`：按字幕变化逐段检查全部可见文字；
- `系统化全量 OCR`：对全部字幕区间运行 OCR 并人工复核；
- `抽样 OCR`：只检查部分帧；
- `未检查`：不得输出精确字幕。

没有执行系统化全量 OCR 时，不得使用该名称。时间只精确到实际证据粒度；0.5 秒抽帧得到的边界写成约值，不得冒充逐帧剪辑点。

## 核验数字与敏感宣称

出现数字、等级、百分比、材料产地、成分、抑菌/除螨/健康、安全、耐久、价格、销量、第一/最佳或儿童贴身用品时，读取 [references/claim-evidence.md](references/claim-evidence.md)，建立：

`原始宣称 → 出现位置 → 直接可见证据 → 外部资质要求 → 证明强度 → 采用决策`

不得用揉捏、拉伸或特写替代检测、成分、产地、效果或长期性能证明。涉及未成年人和贴身衣物时，优先平铺、手部、产品特写或合规人台；避免敏感身体展示、羞辱家长和无依据的卫生恐惧。

## 每条视频建立独立记录

在可获得时记录：

- 排名、日期、榜单、作者类型、作者、标题、商品、价格带和广告状态；
- 时长、播放、3 秒完播、商品点击、点击率、点击转化和 GMV；
- 点赞、评论、分享、收藏和相关同类基准；
- 证据覆盖：视频、音频、画面文字、转写、平台分析和指标。

批量分析时，先完成每条视频的独立记录，再综合多视频规律。

批量记录使用 [references/video-record-schema.md](references/video-record-schema.md)。缺少作品 ID、榜单截图、指标或平台阶段时保留 `unknown` 和覆盖状态，不从聚合描述反推单条记录。

## 先还原视频，再解释机制

必须使用以下三层顺序：

1. **视频事实层**：证据边界、整体视听画像、素材模块图和结构化分段；
2. **机制判断层**：停留、理解、证明、信任、节奏、转化和商家/达人逻辑；
3. **采用决策层**：可直接采用、有条件采用、不建议采用、原创改编和下一步验证。

视频事实层未完成前，不输出可复制公式或改编建议。

事实层在可见或可听时记录：

- 时间范围和阶段目标；
- 画面特点；
- 景别和机位/角度；
- 主体和动作；
- 场景和环境；
- 口播和画面文字；
- 卖点标签；
- 细节展示和证据强度；
- 转场和节奏；
- 音乐/音效处理和商品露出方式。

必填字段没有证据时，使用“未知”“画面不可见”或“未检查”，不要通过合并字段掩盖缺失。

声音层至少分开记录：

- 是否完整听取；
- 人声/说话人、语速、重音和可懂度；
- 背景音乐是否存在、强弱和作用；
- 音效出现位置和作用；
- 音画、字幕是否同步；
- 音量统计与主观听感的边界。

## 必要时使用两级分段

连续单来源视频按创意转折分段。混剪、二创、多人素材或长视频重复脚本时：

1. 先根据人物、声音、场景、厨房/地点、画幅、字幕、商品款式或剪辑风格识别素材模块；
2. 映射所有素材模块；
3. 再拆每个重要模块内部的传播阶段；
4. 区分画面切换速度与信息推进速度。

不要强迫所有视频使用固定段数。按真实传播目的变化拆分，例如：

1. 钩子或结果揭示；
2. 痛点和使用场景；
3. 核心利益；
4. 演示或对比；
5. 证明、细节或原理；
6. 人群和场景扩展；
7. 信任、优惠、保障或行动指引。

制作完整拆解、比较、评分或公式时，读取 [references/framework.md](references/framework.md)。

## 解释传播与转化机制

使用来源证据回答：

- 开头为什么可能让目标人群停留？
- 突出了哪种痛点、欲望、身份或场景？
- 利益点只是口头宣称，还是有可见证明？
- 哪些内容降低不确定性或建立信任？
- 结构是否从注意推进到理解、相信和行动？
- 哪些是商品专属表达，哪些能迁移到其他商品？

区分商家和达人逻辑：

- 商家视频通常以商品清晰度、标准化演示、功能覆盖和结构化证明为主；
- 达人视频通常从人物、场景、观点、亲身体验或独特表达切入，再借助个人可信度建立信任。

任务涉及抖店、挂车成交榜、商家/达人比较或 20 条初始样本校准时，读取 [references/doudian-baseline.md](references/doudian-baseline.md)。

## 生成读者友好的交付物

完整报告使用 [assets/breakdown-template.md](assets/breakdown-template.md)。

- 需要时把原始 ASR/OCR/场景文件放入证据目录。
- 默认交付经复核的 Markdown 报告。
- 转写细节重要时，交付经复核的 Markdown 或 SRT。
- 用户要求机器可读 JSON 时，使用稳定字段；尽量直接保存可读 UTF-8 中文，不输出 token/logit，并为不确定内容附证据状态。
- 分开呈现直接观察、平台提供和分析推断。
- 可省略不相关的可选章节，但不得因字段相近而省略必填视觉字段。

正式 JSON 写入后，至少检查：

```bash
python3 -m json.tool deliverables/breakdown.json
```

并确认文件中是直接可读中文。原始自动转写 JSON 即使格式有效，也不能替代 `deliverables/breakdown.json`。

## 仅在有用时评分

只有比较、排序或用户明确要求评分时，使用框架中的 100 分量表。每个分数必须引用具体证据，不得作为表现保证。

## 根据反馈安全迭代

用户纠正分析时：

1. 判断问题来自证据覆盖、观察、推断、术语、权重还是输出格式；
2. 先修正当前结果；
3. 提出最小可复用规则；
4. 仅在用户要求更新或优化技能时修改技能；
5. 保留相反案例，不把单条反馈泛化为绝对规则；
6. 修改后重新校验技能。

不维护单独的更新日志。长期规则写入 `SKILL.md`，详细标准写入 `references/framework.md`，带日期的样本证据写入对应基线文件。

抖店或其他平台基线只作为带日期校准材料。用户要求“当前榜单”“最新规律”或当前账号结果时，重新进入后台获取快照；不得把历史基线包装成当前数据。

## 完成硬门

- 完整视频报告中的画面特点、景别/机位、主体/动作、场景、卖点标签、细节/证据和转场/节奏必须填写或明确标为不可获得。
- 视频事实层完成前，不得输出建议。
- 原始 ASR JSON 或未经复核的转写不得作为可读交付物。
- 判断信息推进前，检查后续镜头是否新增卖点、证明、顾虑、场景或优惠，不把快切自动视为推进。
- 混剪视频不得跳过素材模块图。
- 使用抽帧、ASR、OCR、平台分析或外部元数据时，必须附依赖与证据清单。
- 本地视频完整报告必须生成带时间戳联络表；联络表失败时明确说明并保留逐帧检查证据。
- 声音未完整听取时，声音、音乐、音效和语气必须标为未检查。
- 数字、等级、材质、功效、健康、安全和价格宣称必须进入宣称证据矩阵。
- 只有0.5秒或1秒抽帧时，时间边界必须标为约值。
- 不把人工核字、抽样 OCR 和系统化全量 OCR 混为一谈。
- 没有排名或表现依据时，不称视频为“爆款”。
- 不把点赞等同于销售。
- 不把可检索榜单样本描述成全市场官方销量排名。
- 不复制原素材、台词、音乐、布景或表演，只迁移传播机制。
- 不隐瞒音频缺失、阶段不可访问、列表截断、登录阻断或平台免责声明。
- 最终必须给出明确的可复用决策或创意方向，不能只做逐镜头复述。
- 改编方案必须指定一个优先实验变量、保持不变项、成功指标和失败后处理，不用一条新脚本同时验证多个假设。
