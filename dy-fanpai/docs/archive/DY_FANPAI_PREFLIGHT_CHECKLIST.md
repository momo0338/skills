## 4. 到对应 Live 阶段前需要用户决定或提供

这些事项不阻止 WP0、WP1 和 Mock/离线开发。

### U2 Skill 实机验收宿主

选择至少一个实际 Agent 宿主，验证安装、自然语言触发、费用/人工闸口暂停和恢复。安装路径以目标宿主的官方机制和现场探测为准，不预设固定目录。

### U3 剪映实机环境

Full Live 前提供或指定：

- Windows/WSL 或其他经验证可用的机器；
- 目标剪映版本；
- 草稿目录；
- 允许安装的 `pyJianYingDraft` 兼容版本。

缺少时，剪映代码和 Mock 可以完成，但不能宣称实机验收完成。

### U4 私有千川方法论包

如果要求“完整复现原作者 B 模式方法论”，需要提供合法可用的私有方法论包。否则 B 模式按公开规则实现，并标记“私有方法论 parity 未验收”。

### U5 合法音色与语音环境

如果要求完成 TTS/换声 Live，需要提供合法目标音色，并允许准备 CosyVoice/Seed-VC 隔离环境。否则相关接口、Mock 和降级路径可以完成，但不能宣称 Live 完成。

### U6 真实服务凭证、素材授权和预算

到某项 Live Pilot 前再提供该项所需内容：

- Ark、Kimi、即梦、小云雀账号或凭证；
- 对应模型、区域和可用额度；
- 合法测试视频、产品图、人物锚图、产品事实；
- 人脸、声音和参考视频授权，以及允许上传的 Provider；
- 本轮总预算或调用上限。

未批准时只能运行 Mock、dry-run 和离线测试。

### U7 是否创建远端仓库

本地开发不需要远端。若需要 GitHub/GitLab 远端，届时由用户明确授权创建、选择可见性并授权推送；默认不自动执行外部写操作。
